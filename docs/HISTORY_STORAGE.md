# Сводки и срок хранения 0.11

Каждая публикация экономики дополняет минутные `history_rollups`: количество наблюдений
и статусов, причины блокировок, число полных/положительных условных оценок, min/max/mean
условного результата. Это статистика повторных наблюдений, не сделки и не накопленный PnL.
Поле `net_sum_usdt` служит для вычисления среднего; его нельзя считать доходом.
Неизвестная оценка не заменяется нулём. Отсутствующая минута означает отсутствие наблюдений,
интерполяции и предположения о непрерывном uptime нет.

Ключ сводки: минута UTC, направление и SHA-256 полного policy экономики. Разные бюджеты,
горизонты funding, профили комиссий, фильтры оборота/влияния/времени и расходы не смешиваются.
Одинаковые настройки разных сессий в одной минуте объединяются как наблюдения.
Сводка хранится в одной транзакции с исходным снимком; checkpoint предотвращает повторный
подсчёт. При открытии старой базы за публикацию обрабатывается не больше 25 исходных снимков.
Полное заполнение старой истории можно выполнить отдельной командой.

```powershell
# Минутные сводки, последние 100 корзин, только чтение
.\.venv\Scripts\python.exe -m arbitrage.history --database data\market.sqlite3 --summary --limit 100
# Сводки одного направления; since inclusive, until exclusive по началу минуты UTC
.\.venv\Scripts\python.exe -m arbitrage.history --summary --pair 'bitcoin|okx:BTC-USDT-SWAP|mexc:BTC_USDT' --since-ms 1793664000000 --until-ms 1793750400000
# Заполнить агрегаты всей старой базы, не удаляя исходные данные
.\.venv\Scripts\python.exe -m arbitrage.maintenance --database data\market.sqlite3 --aggregate-only --apply
# Предварительный расчёт очистки: хранить подробные данные за 7 дней
.\.venv\Scripts\python.exe -m arbitrage.maintenance --database data\market.sqlite3 --keep-days 7
# Применить очистку, создать новую резервную копию и уплотнить файл
.\.venv\Scripts\python.exe -m arbitrage.maintenance --database data\market.sqlite3 --keep-days 7 --apply --compact
```

Чтение сводок возвращает `aggregation.caught_up` и количество ещё не обработанных исходных
снимков. Лимит — последние 1–1000 корзин, с хронологической выдачей; он не означает всю историю.
Границы времени выбирают полные минуты по start_ms, частичные минуты не пересчитываются.

Очистка без `--apply` открывает базу только для чтения и не создаёт таблиц или копий.
При применении сначала блокируются изменения других писателей, затем SQLite Backup API
создаёт согласованную копию по новому пути. Существующий файл резервной копии не перезаписывается.
Все оставшиеся исходные снимки агрегируются, после чего удаление выполняется одной транзакцией.
При ошибке агрегации/удаления транзакция откатывается. Копия уже существует и при откате.

Удаляются только подробные снимки старше эффективной границы и целиком завершённые
эпизоды событий. Незавершённые эпизоды и эпизоды, пересекающие запрошенную границу,
сдвигают её назад к своему началу с запасом 3 секунды на исходные котировки.
Preview показывает запрошенную/эффективную границы, число защищённых эпизодов и строки удаления.
Последний ID каждой таблицы (у котировок — по бирже) остаётся как служебный якорь,
чтобы SQLite не переиспользовал ID источников и не нарушил checkpoint.
Это может оставить несколько старых записей; их возраст не делает их свежими.

Минутные агрегаты не удаляются. После удаления подробных данных старый расчёт можно
воспроизвести только из резервной копии; сводка не содержит полного стакана.
`--compact` выполняет VACUUM после фиксации очистки: возвращает свободные страницы файловой
системе. Без него уменьшение числа строк не обязано уменьшать файл. Уплотнение и большой
backfill следует запускать при остановленном мониторе. Ошибка VACUUM не отменяет уже
зафиксированную очистку; исходные данные доступны в созданной резервной копии.

В 0.13 включено отдельное фоновое обслуживание с порционными архивами и пределами
хранения: [AUTOCARE.md](AUTOCARE.md). Описанная выше ручная команда по-прежнему создаёт
полную копию, которую автоматика не удаляет. Резервная копия занимает дополнительное
место: уменьшение основной базы не означает уменьшения общего объёма всех файлов.
В 0.12 новый запуск закрывает эпизоды, оставшиеся без ended после аварии;
история защищена до закрытия и истечения обычного срока хранения:
[FUNDING_RECOVERY.md](FUNDING_RECOVERY.md).
Проверка на копии живой базы: [HISTORY_STORAGE_CHECK.md](reports/HISTORY_STORAGE_CHECK.md).
