# Публикация рыночного снимка — замер до и после

Пункт 18 аудита. Снимок сериализуется один раз в рабочем потоке перед публикацией.
HTTP получает готовое тело и ETag. Пока готовится следующий снимок, HTTP отдаёт
предыдущий. SSE сообщает о готовности после публикации.

Сравнивались `d035877` и `ac3c558` на одной машине, с одинаковыми версиями
Python, Node.js, aiohttp и Chrome. Стенд использует 1 000 монет, 12 000 ног,
66 000 направлений и 80 строк таблицы. Для каждого сценария сделан 21 замер после
пяти прогревов. HTTP-запросы идут по loopback. Биржи и рабочая база не участвуют.

| Операция | До, p50 / p95, мс | После, p50 / p95, мс |
| --- | ---: | ---: |
| Сборка с холодными кэшами | 109,025 / 168,235 | 115,614 / 169,420 |
| Сборка с прогретыми кэшами | 83,672 / 104,684 | 92,243 / 140,484 |
| Подготовка к публикации | 0,005 / 0,006 | 9,707 / 12,785 |
| Первый HTTP 200 после публикации | 15,682 / 16,208 | 6,340 / 7,600 |
| Повторный HTTP 200 | 7,208 / 8,954 | 6,606 / 16,682 |
| Условный HTTP 304 | 1,644 / 1,858 | 0,455 / 2,133 |
| HTTP 200 со сжатием gzip | 14,231 / 15,503 | 14,019 / 15,456 |
| Синхронное обновление 80 строк в Chrome | 9,6 / 10,2 | 9,6 / 10,4 |
| От команды публикации до обновления таблицы по SSE | 85,7 / 96,7 | 87,0 / 93,4 |

Медиана первого HTTP-ответа после публикации снизилась на 60%. Подготовка
снимка теперь занимает 9,7 мс по медиане. Ускорение от команды публикации до
таблицы не подтверждено. Размер HTTP-тела сохранился на уровне 3 884 112 байт
без сжатия и 120 575 байт с gzip. Алгоритмы сборки снимка и отрисовки таблицы
совпадают в обеих версиях. Их время зафиксировано как контрольный показатель,
сборку и отрисовку потребуется измерять отдельно перед следующими правками.

Регрессии проверены 50 Python-тестами, 17 Node.js-тестами и Playwright в Chrome.
Добавленный тест задерживает сериализатор и проверяет доступность прежнего
тела и ETag до готовности новой версии.

Запуск из корня репозитория после установки зависимостей проекта и Playwright

```powershell
node benchmarks/market_pipeline.cjs
```

`ARBITRAGE_PYTHON` задаёт путь к Python. `ARBITRAGE_TARGET` позволяет прогнать
тот же стенд на другом локальном checkout. `PLAYWRIGHT_CHANNEL` выбирает
установленный браузер, например `chrome`.
