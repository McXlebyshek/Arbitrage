# Проверка settlement marks 0.26 — 2026-11-05

Первый адаптер точных исторических settlement marks — Binance USD-M.
Методика и первичные источники: [SETTLEMENT_MARKS.md](../SETTLEMENT_MARKS.md).

12 новых тестов проверяют:

- Конкретный HTTPS endpoint, параметры окна, таймаут и запрет redirect.
- Symbol/время/Regular rateType/совпадение ставки и конечную положительную цену.
- Отсутствие подстановки last/другой цены при пропуске markPrice.
- Конфликтующие/одинаковые дубликаты и атомарное отклонение повреждённой страницы.
- HTTP 429, формат/сеть без автоматического повтора.
- Пагинацию, движение курсора и бюджет страниц.
- Валидацию запроса, отсутствие сети для пустого окна.
- Binance-ногу и явную неподдержанную вторую ногу с null итогом.
- Полный искусственный расчёт при сочетании с ручными ценами второй ноги.
- Повтор/кэш/refresh, исправление ставки и защиту от гонки после скачивания.
- Совпадение реестра и read-only загрузку конкретной позиции/replay-проверку.
- CLI funding --fetch-prices → сверку → запись результата/отчёта с заглушкой загрузчика.

Полный набор: **234 Python-теста и 11 проверок JS прошли**.

Публичная проверка: `validate_settlement_marks_live.py` выполнила **два GET**
к Binance для BTCUSDT, без ключей и операций с ledger/счетами. Проверенное событие:
fundingTime=1793865600000, fundingRate=0.00010000.
Исходная и скачанная markPrice совпали: **80356.91065217** в нативных единицах.
Машинный отчёт: [SETTLEMENT_MARKS_LIVE_METRICS.json](SETTLEMENT_MARKS_LIVE_METRICS.json).

Это проверка публичного поля цены, **не рыночная доходность и не живой paper-цикл**.
Другие биржи, фоновая сверка, длительная проверка и расширенная статистика остаются
в плане. UI этой версией не изменяется. Этап 11 остаётся частичным.
