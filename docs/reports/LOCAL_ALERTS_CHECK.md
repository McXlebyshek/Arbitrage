# Локальные уведомления 0.19 — 2026-11-05

Реализованы локальная запись и консольные сообщения для подтверждения условного
сценария и потери условий ранее объявленного эпизода. Порог/число подтверждений
задаются существующей политикой сигналов, cooldown — отдельной опцией (60с по умолчанию).
Внешняя доставка, звук и визуальная панель пока отсутствуют; этап 10 выполнен частично.

157 Python-тестов прошли: прежние 149 и 8 новых проверок.
Проверены дедупликация event ID/эпизода, свежесть и согласованность confirmed,
количество подтверждений, cooldown между сессиями, lost/stop/recovery,
закрытие только ранее объявленного эпизода, атомарный откат вместе с сигналами,
отключение и неверная политика, read-only чтение старой/отсутствующей базы,
архивирование до удаления и монотонный курсор после очистки.
HTTP-тест проверяет GET, лимит/курсор и запрет POST для `/api/alerts`.
11 проверок JavaScript-модели графиков остаются успешными.

Публичный запуск в отдельной базе длился 61,41с, 30 публикаций, до 50 котировок
и 200 направлений. Каталог Gate завершался RequestTimeout; код монитора 1 отражает
неполный охват/свежесть, не ошибку уведомлений. Не выполнен полный прогон шести площадок.
В источнике 19 appeared, 19 ended и 34 reason_changed; confirmed не наблюдались.
Журнал правильно остался пустым, итоговый JSON показывает enabled=true и 60с cooldown.
Положительные уведомления, дедупликация и потеря после них проверены контролируемыми
тестами; реальные прибыльные сигналы этим запуском не подтверждены.
SQLite integrity_check=ok, отдельная CLI-команда прочитала пустой журнал без изменений базы.

Новый журнал сохраняется в одной транзакции с исходными сигналами; печать происходит
после commit. Для показа консоли ровно один раз при аварии гарантий нет, запись в базе
остаётся источником истории. Удаление выполняется общей фоновой политикой сводок.

Следом: панель журнала в UI и пользовательские настройки доставки/прочтения.
Telegram подключается только после отдельной настройки получателя.
