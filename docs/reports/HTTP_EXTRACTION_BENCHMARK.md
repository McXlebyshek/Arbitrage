# Разделение серверных модулей — проверка до и после

Пункт 22 аудита. `monitor.py` отвечает за запуск, цикл сбора и планирование
ранних котировок. HTTP и SSE находятся в `market_monitor/http_api.py`,
кэш стаканов — в `books.py`, сборка снимка — в `snapshot.py`,
оценка издержек — в `economics.py`. Размер `monitor.py` сократился с 1 047 до 529 строк.

Перед переносом и после него прошёл один и тот же HTTP-контракт на
синтетических данных. Он проверяет статусы и тела снимка, health, карточки,
стакана, VWAP-спреда и оценки издержек, условный HTTP 304 и переиспользование
запросов стакана между маршрутами. После переноса также прошли
52 Python-теста, 17 Node.js-тестов и Playwright.

Стенд сравнил `b749633` и `e715aa0` с 12 000 рынками на той же машине.
21 замер после пяти прогревов.

| Сценарий | До, p50 / p95, мс | После, p50 / p95, мс |
| --- | ---: | ---: |
| Прогретая сборка снимка | 71,168 / 76,745 | 71,981 / 78,989 |
| Первый HTTP 200 после публикации | 6,169 / 8,573 | 6,261 / 8,195 |
| Повторный HTTP 200 | 6,543 / 10,701 | 6,544 / 9,780 |
| HTTP 304 | 0,403 / 1,938 | 0,402 / 0,575 |
| От команды публикации до таблицы | 85,9 / 92,8 | 83,5 / 96,5 |

Размер тела остался 3 884 112 байт без сжатия и 120 575 байт с gzip.
Медианы сборки и HTTP сопоставимы. Оба прогона этого сценария дали p95
прогретой сборки ниже 100 мс. В [предыдущем замере](SNAPSHOT_BUILD_BENCHMARK.md)
p95 был выше этого порога. Влияние сборки на живой event loop предстоит измерить.
