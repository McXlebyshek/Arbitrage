# Сборка рыночного снимка — замер до и после

Пункт 17 аудита. До правки монитор кэшировал допуск каждого рынка, но каждый
цикл заново искал совместимые ноги и формировал маршруты инструментов.
После правки совместимые группы и маршруты переиспользуются до смены каталога.
Ранние котировки используют свой набор источников. Цены, фандинг и статусы
обновляются на каждом снимке. Список инструментов в кэше перестраивается
при замене каталога, в том числе при обнаружении дублирующегося маршрута.

Стенд `benchmarks/market_pipeline.cjs` сравнил `5a5f789` и `8239473` на
12 000 рынках, 66 000 направлениях и 80 строках Chrome. В каждом прогоне
21 повтор после пяти прогревов. Котировки синтетические.

| Сценарий | До, p50 / p95, мс | После, p50 / p95, мс |
| --- | ---: | ---: |
| Сборка при неизменных каталогах | 88,871 / 110,017 | 74,269 / 111,395 |
| Сборка с холодными кэшами | 114,121 / 169,145 | 120,030 / 178,049 |
| Первый HTTP 200 после публикации | 6,293 / 7,612 | 5,961 / 6,190 |
| От команды публикации до таблицы | 86,9 / 96,4 | 85,9 / 114,4 |

Медиана прогретой сборки снизилась на 16,4%. Холодная медиана выросла на 5,9 мс.
В отдельном замере `tracemalloc` после удаления готового снимка и сборки мусора
монитор удерживал 6,31 МБ до правки и 10,01 МБ после. Размер опубликованного
JSON сохранился на уровне 3 884 112 байт без сжатия и 120 575 байт с gzip.
Замер от команды публикации до таблицы начинает отсчёт после сборки рыночных
данных и служит контрольным показателем для интерфейса.

Побайтово совпали четыре сравнения с прежним кодом, включая свежий снимок,
истёкшие котировки, подмножество источников и замену каталога. Прошли
51 Python-тест, 17 Node.js-тестов и Playwright в Chrome.

Пункт остаётся частичным. Для решения о переносе сборки в отдельный поток
нужно измерить задержку event loop под живой нагрузкой. В локальном прогоне
p95 прогретой сборки остался выше 100 мс.
