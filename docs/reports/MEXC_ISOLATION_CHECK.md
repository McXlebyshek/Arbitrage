# Изоляция восстановления MEXC, версия 0.40.0

При пересборке одного стакана MEXC прежний общий обработчик ожидал REST внутри чтения WebSocket. Из-за этого задерживались кадры остальных четырёх контрактов группы. Ошибка REST переходила в обработчик переподключения всей группы.

Теперь цена проблемного контракта удаляется синхронно, запрос снимка и повторы выполняются отдельной задачей. Группа продолжает читать кадры остальных инструментов. Один контракт может иметь не более одной такой задачи. Буфер содержит до 128 последних кадров с исходным временем получения. Восстановление проверяет последовательность диапазонов, затем публикует только последнюю проверенную котировку. REST без следующего подтверждающего WS-диапазона не создаёт котировку.

При загрузке или проверке данных с ошибкой повтор выполняется через 1, 2, 4 с и далее до 30 с, через общий REST-лимитер MEXC. Если буфер уже не связывается со снимком, требуется новый снимок. Закрытие соединения отменяет и дожидается всех его запросов восстановления. Проверка свежести после восстановления использует фактический текущий момент, исходное время источника и исходное время получения.

## Локальная проверка

Стенд подключает обычный LiveExchange к локальным HTTP/WS-серверам и пропускает котировки через штатный scanner.scan. Пять искусственных контрактов на одном сокете сначала дают пять пригодных котировок. Затем у ATOM пропускается версия, а следующий REST-запрос задерживается на 3,6 с и возвращает HTTP 503. Последующие запросы успешны.

| Наблюдение | 0.39 | 0.40 |
|---|---:|---:|
| Минимальное число пригодных соседей во время сбоя ATOM | 0 из 4 | 4 из 4 |
| Выборки с четырьмя пригодными соседями | 54/134 | 92/92 |
| Восстановление ATOM | 6,831 с | 4,694 с |
| Повторные WS-подключения | 1 | 0 |
| Пригодные котировки после восстановления | 5 | 5 |

Это контролируемый сценарий. Он показывает влияние задержанного и неуспешного HTTP-запроса на обработчик, а поведение публичных TLS-сбоев дополнительно наблюдается в рыночных прогонах. [До исправления](MEXC_ISOLATION_BEFORE.json) · [После исправления](MEXC_ISOLATION_AFTER.json).

Проверены также отмена ожидающего запроса перед новым соединением, повтор после разрыва при переполнении буфера, обязательность WS-подтверждения после REST и сохранение возраста старых кадров при воспроизведении. Счётчик ошибок восстановления сохраняется при замене группы.

## Публичная проверка

В отдельном пятиминутном стенде 0.40 работали шесть бирж, 20 активов, Gate OBU по пять контрактов на соединение и Binance depth5@500ms / 20. После 60 с прогрева сохранено 115 выборок по 20 инструментам каждой биржи.

| Биржа | Средняя свежесть | Худшая полная минута |
|---|---:|---:|
| Binance | 100% | 100% |
| Bybit | 99,70% | 99,31% |
| OKX | 99,48% | 98,79% |
| Bitget | 96,87% | 95,86% |
| Gate | 99,70% | 99,48% |
| MEXC | 96,83% | 96,03% |

Переподключений у всех бирж 0. MEXC загрузил 20 начальных книг, ошибок восстановления 0. Сбой REST в этом рыночном окне не возник. CPU монитора после прогрева 19,59% одного ядра, пиковая RSS 527,1 МиБ, p95 публикации 98,42 мс. Все 444 HTTP-ответа API успешны, market SQLite 131 149 824 байта, integrity_check=ok. Перезапуск трёх paper-процессов на 150,25 с, архив и блокировка правил после остановки прошли. Код завершения монитора 0 означает полное покрытие последнего активного снимка; в других снимках были пропуски, отражённые в таблице.

В базе 27 событий confirmed, максимум условного сценария 0,363645 USDT при пороге входа 1 USDT. Виртуальных позиций не было. Прошли 324 Python-теста и 11 JS-проверок. Суточная проверка и положительный живой paper-цикл остаются открытыми. [Полные метрики и минутные окна](MEXC_ISOLATION_FULL_V040.json).

Следующий шаг — более длительное наблюдение 0.40 с новыми счётчиками ошибок восстановления MEXC, оценкой пропусков по инструментам и сохранением штатных порогов Paper.

## Запуск проверок

Из корня проекта, с новым файлом/каталогом:

```powershell
.\.venv\Scripts\python.exe validate_mexc_isolation.py --output data/mexc-isolation-next.json
.\.venv\Scripts\python.exe validate_paper_live.py --directory data/mexc-isolation-next --duration 300 --port 8777 --rules --gate-stream obu
```

Публичный стенд запускается с отдельной SQLite. Обычный монитор включает восстановление MEXC автоматически при следующем запуске.
