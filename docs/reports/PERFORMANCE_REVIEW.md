# Оптимизация текущего монитора — 2026-11-11

Проверены сборщики `market_monitor/`, HTTP API и SQLite в `monitor.py`, построение
связок, фильтры, сортировка и обновление интерфейса. `OLD/` не участвует в запуске
или импортах. Архив и пользовательские рыночные базы не изменялись.

## Изменения

1. При обновлении WS/ранних котировок пересчитываются только затронутые направления.
   Остальные объекты связок сохраняются. Замены снимаются при отключении потока,
   истечении срока или новом общем снимке. Полный пересчёт остаётся при изменении
   исходного снимка/карточек, истечении котировок, ставок, оценки капитализации,
   срока кэша деталей и откате часов. Учтено наступление допустимого времени
   первоначально будущих котировок. Фоновые таймеры используют тот же путь.
2. Для сгруппированной выдачи лучшая связка монеты выбирается за один проход,
   затем сортируются группы. Число скрытых направлений, порядок при равных
   значениях, неизвестные значения, сортировки и фильтры сохранены.
3. Поиск, выбранные биржи и числовые пороги готовятся один раз на отбор.
   Поиск по нативному тикеру вычисляется один раз на монету. Убрано создание
   временного объекта всех порогов и преобразование их значений для каждой связки.
4. `/api/markets` поддерживает ETag и `If-None-Match`. Неизменившийся снимок
   возвращает HTTP 304 без тела. Клиент не разбирает повторно JSON; обновление
   деталей и таймеры свежести продолжают работать. Хэш содержимого защищает
   от совпадения локального номера версии после перезапуска сервера.

## Измерения

Искусственный набор: 1 000 монет, 12 000 ног, 66 000 связок; обновление
30 WS-пар. Медиана 15 повторов после трёх прогревов, одинаковые данные и часы.
За исходную версию взяты файлы перед этой порцией, сохранённые в рабочей копии
`performance-review-20261111/original`. Полные результаты связок и выдачи
до/после сравниваются перед измерением.

| Операция | До, мс | После, мс |
| --- | ---: | ---: |
| Обработка события 30 WS-пар | 304,759 | 0,547 |
| Фильтрация и сгруппированная сортировка | 89,425 | 14,262 |

Это скорость вычислений JavaScript в Node на данной машине, без DOM, сети и
ожидания бирж. Числа не означают такое же ускорение всего приложения.
Дополнительная таблица индексов требует O(числа связок) памяти; взамен частые
обновления не создают заново весь набор объектов.

## Проверки

- 46 Python-тестов и 17 Node.js-тестов.
- 1 300 вариантов параметров фильтра/режима сравниваются со старым отбором:
  пять режимов, группировка, поиск по алиасу, избранное, пороги, валюты, сортировки,
  живая и демонстрационная семантика.
- Точечный пересчёт сверяется с полным при замене и снятии котировок, исчезновении
  временных связок, истечении деталей/фандинга/капитализации/цен, смене снимка
  и переводе часов назад. Для 30 WS-пар создаются 60 направлений, остальные
  объекты сохраняют идентичность.
- Проверен HTTP 304, обновление ETag при новой публикации, отсутствие тела
  у неизменившегося ответа и восстановление HTTP 200 при изменении.
- Playwright MCP оказался занят другим профилем. Использован установленный
  Playwright с отдельным headless Chrome и временным локальным тестовым сервером.
  На искусственных 13 200 связках прошли получение SSE, обновление и сохранение
  незатронутых объектов, сортировка, поиск, карточка, истечение фандинга,
  последовательность HTTP 200/304/200. Ошибок JavaScript нет. При ширине 390 px
  страница не переполняется; таблица сохраняет внутреннюю горизонтальную прокрутку.
  [Протокол](performance-browser.json) · [Мобильный экран](performance-mobile.png).
- Синтаксис Python/JavaScript проверен. Зависимости не менялись; Ruff отсутствует.
  Реальные сборщики и постоянный UI не перезапускались.

## Что остаётся

- `renderTable()` по-прежнему заменяет таблицу целиком. При частом потоке следующим
  кандидатом является обновление изменённых строк и объединение отрисовок в кадр;
  для него нужен отдельный замер DOM и проверка фокуса, раскрытых элементов и прокрутки.
- Полный рыночный снимок ждёт все REST-источники. Отказ медленной площадки может
  задержать публикацию остальных. Независимая публикация источников затрагивает
  смысл времён/синхронности, поэтому не вводилась без отдельной проверки.
- История уже пишется пакетно раз в минуту вне event loop, выборка использует
  ключ `(market, slot)`, очистка — индекс `slot`. WAL или постоянное соединение
  не добавлялись без измерения конкуренции на копии большой базы.
- Длительная проверка с реальными потоками и измерение общей задержки интерфейса
  остаются в ROADMAP. Текущая проверка не доказывает суточную устойчивость.
