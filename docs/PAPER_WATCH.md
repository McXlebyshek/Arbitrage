# Закрепление и автоматическая переоценка 0.24

Монитор теперь читает открытые live paper-позиции из `data/paper.sqlite3` и
удерживает REST-сбор их ног независимо от кандидатов scanner. Сам монитор
paper-журнал не изменяет. Для записи автоматических переоценок есть отдельный
процесс, который запускается только пользователем.

```powershell
Set-Location G:\Arbitrage
# Окно 1: перезапустите монитор после обновления
.\Start-Monitor.cmd
# Окно 2: после ручного paper-входа включите переоценку
.\Start-Paper-Watch.cmd
```

CLI для одного прохода или постоянного режима:

```powershell
.\.venv\Scripts\python.exe -m arbitrage.paper_watch
.\.venv\Scripts\python.exe -m arbitrage.paper_watch --watch
```

Ctrl+C завершает watcher; монитор и виртуальные позиции остаются. Автоматические
входы/закрытия отсутствуют. Funding не сверяется этим процессом автоматически.
Требуется существующая live-позиция; replay-журналы игнорируются и не изменяются.

## Какие данные закрепляются

Каждые 2с фоновая задача монитора читает paper-журнал через SQLite mode=ro
(ожидание блокировки до 0.2с). Отсутствующий файл не создаётся. Сначала рассматриваются
первые 10 открытых позиций в порядке создания, до 20 различных ног. Пересечения
ног с другими позициями/кандидатами объединяются, одинаковый стакан не запрашивается
дважды. Проверяется совместимость с текущим реестром и включёнными биржами.

Лимит не скрывается: `economics.paper_collection` содержит state, open_count,
limit, omitted_by_limit, skipped и checked_at_ms. Некорректные позиции из первых
10 пропускаются с причиной; оставшиеся сверх десятой не подставляются вместо них.
После закрытия ноги удаляются при следующем обновлении, если их не удерживают
другие позиции или текущие кандидаты. Replay и пустой/старый формат базы отмечаются
отдельными состояниями, а не становятся live-позициями.

Временная ошибка чтения сохраняет прежнее закрепление до 10с от последнего
успешного чтения, с `state=read_error` / `retained_during_grace`. После этого
закрепления сбрасываются; причина остаётся видна. Восстановление чтения возвращает
их. Удаление файла или обнаружение replay немедленно снимает закрепления.

Дополнительные legs проходят существующие общие лимиты CCXT и MEXC; на биржу
по-прежнему максимум три одновременных задачи глубины. Свежесть данных не
обещается самим фактом закрепления: сетевой сбой/ограничение остаётся причиной
отказа в оценке. Funding/оборот для закреплённых контрактов также входят в
существующий сбор, но это не загрузка settlement mark prices.

В `economics.inputs` публикуется объединение стаканов кандидатов и закреплений.
`economics.rows` по-прежнему содержит только кандидатов: закрепление не создаёт
новый confirmed-сигнал. История входа и исходное количество позиции не меняются.

Путь можно изменить у обоих процессов:

```powershell
.\.venv\Scripts\python.exe -m arbitrage --paper-database data/custom-paper.sqlite3
.\.venv\Scripts\python.exe -m arbitrage.paper_watch --database data/custom-paper.sqlite3
```

Закрепление работает в основном WebSocket-мониторе при `--economics-pairs > 0`.
`--economics-pairs 0` отключает enrichment вместе с закреплением; старый REST-режим
этой фоновой задачи не содержит. Биржи, не включённые в запуск монитора, не
подключаются скрыто — позиция пропускается с `paper_exchange_not_enabled`.

## Переоценка и состояние

Watcher каждые 2с читает latest.json и вызывает обычный PaperLedger.value для
тех же первых 10 совместимых live-позиций. Он проверяет текущую свежесть стаканов
даже при повторе того же снимка. Повтор валидного снимка не создаёт событие marked;
при новом успешном снимке событие и оценка записываются атомарно. После перезапуска
идемпотентность сохраняется через source_hash в журнале.

Старый/остановленный/неполный снимок, нехватка глубины, изменение контракта или
времени приводят к blocked. Последняя успешная оценка и открытая позиция сохраняются.
Ошибка одной позиции не отменяет обработку остальных. При ручном закрытии в другом
процессе watcher не открывает её заново.

Статус атомарно записывается в `data/paper-watch.json`; путь задаётся `--status`.
Там видны общий state, состояния каждой позиции marked/already_current/blocked,
ошибка и last_valuation_ms. Консоль показывает изменения состояния.
Статус не заменяет журнал и не подтверждает актуальность прежней оценки.
Если источник недоступен, общий state — snapshot_unavailable/ledger_error.

ОС-блокировка разрешает один watcher на файл paper-журнала. Ручной CLI продолжает
работать через транзакции SQLite. Файл статуса должен быть JSON, отличаться от входов;
существующий JSON без classification=paper_watch_status не перезаписывается.
Уникальные временные файлы при аварии могут остаться рядом со статусом.

Новая оценка сбрасывает funding, поскольку меняется конец его окна. Для свежего
итогового net потребуется новая сверка funding; без неё он null. Журнал marked
растёт при каждом новом успешном снимке: автоматической очистки paper-истории нет.
