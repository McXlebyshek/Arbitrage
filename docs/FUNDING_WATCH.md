# Фоновая сверка funding 0.27

Отдельный процесс сверяет существующие live paper-позиции и сохраняет результат
в том же paper-журнале. Он не открывает/закрывает позиции, не собирает стаканы,
не загружает историю ставок и не блокирует процесс переоценки ожиданием сети.

```powershell
Set-Location G:\Arbitrage
# Без сетевых запросов, только локальная история/кэш
.\Start-Paper-Funding.cmd
# Разрешить точные Binance settlement marks
.\Start-Paper-Funding.cmd --fetch-prices
# Добавить ручные цены другой ноги
.\Start-Paper-Funding.cmd --fetch-prices --funding-prices data/other-leg-marks.json
```

`Start-Paper-Watch.cmd` по-прежнему отдельно переоценивает стаканы. Все процессы
используют транзакции SQLite; новая ОС-блокировка допускает один funding-worker
на ledger и не запрещает ручные команды/переоценку.

Один проход CLI:

```powershell
.\.venv\Scripts\python.exe -m arbitrage.paper_funding_watch --funding-prices data/marks.json
.\.venv\Scripts\python.exe -m arbitrage.paper_funding_watch --watch --fetch-prices --interval 60
```

Пути: `--database data/paper.sqlite3`, `--market-database data/market.sqlite3`,
`--status data/paper-funding-watch.json`, `--registry PATH`. Базы обязательно
разные. Replay игнорируется; отсутствующий ledger/архив не создаётся.
Неизвестные выплаты не заменяются нулём.

## Очередь и расписание

По умолчанию один цикл раз в 60с; допустимый интервал 60–3600с после завершения
предыдущего цикла. Обрабатываются первые 10 открытых позиций и до 5 закрытых.
Закрытые проходят в порядке создания с сохранённым rowid-курсором и возвратом
к началу после конца — ни ошибка старой записи, ни уже полный расчёт не удерживают
очередь навсегда. Это также позволяет обнаружить исправление ставок/ручных цен.
Число пропущенных открытых позиций указано в `selection.omitted_open`.

Сначала проверяется ручной файл цен. Его ошибка останавливает цикл без изменения
позиции и без сети. Ошибка одной позиции помечается blocked; остальные продолжают
обрабатываться. Недоступный импорт, пропуск ставки/цены дают partial по обычным
правилам funding; прежде полный итог при ухудшении покрытия очищается до null.

История ставок остаётся read-only. Её должен обновлять монитор/существующий импорт
funding. Если импорт отстаёт от времени оценки, итог неполон даже при наличии цен.
Settlement marks автоматически доступны только для Binance USD-M; другие ноги
пока требуют предоставленного файла. Механика и контроль покрытия —
[PAPER_FUNDING.md](PAPER_FUNDING.md), [SETTLEMENT_MARKS.md](SETTLEMENT_MARKS.md).

## Постоянный кэш

`paper_settlement_prices` хранит одну принятую Binance-цену на инструмент/время
с соответствующей ставкой и источником. Запись атомарна с funding-расчётом/аудитом.
Изменение стаканов и сброс funding при новой оценке эту таблицу не удаляют.
Цены могут переиспользоваться несколькими позициями того же инструмента/события.
Кэш читается read-only и ограничен окном каждой позиции, до 2000 событий на ногу.
Смена ставки или несовместимый реестр запрещают использование старой цены.

Ручная `paper funding --fetch-prices --refresh-prices` игнорирует кэш и обновляет
сохранённую цену. Исправление только цены на бирже при неизменной ставке в фоне
само не обнаруживается. Автоматической очистки paper-кэша и истории пока нет.

## Сетевой бюджет и восстановление

Без `--fetch-prices` HTTP-запросов нет, но уже сохранённый кэш используется.
С флагом максимум **3 запроса за весь цикл**, а не за каждую позицию. Если бюджет
исчерпан, остальные могут использовать кэш/ручные цены; недостающая сеть помечена
`network_budget_deferred`, итог не придумывается.

Ошибка скачивания прекращает дальнейшие сетевые запросы цикла и включает паузу
минимум на интервал. HTTP 429/418 учитывают числовой Retry-After, с минимумом 60с,
по умолчанию 300с и максимумом 3600с. Это не общий ограничитель всех приложений IP.
Офлайн-обработка остальных позиций во время паузы продолжается.

JSON-статус сохраняет `cursor` и `next_network_ms` атомарно; они восстанавливаются
после перезапуска. Существующий посторонний JSON не перезаписывается; статус не
может совпадать с входами. После аварии могут остаться отдельные временные файлы.
В консоли/статусе видны состояние каждой позиции, время конца funding-окна,
сетевые запросы/пропуски/ошибки. Значения относятся к последней сверке, не к текущему
рынку. Если отдельная переоценка продвинула окно, net снова null до подходящей сверки;
этот процесс с интервалом 60с не гарантирует постоянно заполненный net открытой позиции.

## Проверенный объём

9 новых тестов проверяют очередь/лимиты, идемпотентность, изоляцию ошибок,
кэш после новой оценки, атомарный откат, общий сетевой бюджет и чтение checkpoint
после перезапуска. Искусственный полный CLI-цикл подтвердил ready → повтор без
дубликата → неполный результат после удаления цен, без сетевых запросов.

Длительный совместный живой прогон, другие точные адаптеры цен, расширенная
статистика и автоматические правила paper-входа/закрытия ещё впереди.
