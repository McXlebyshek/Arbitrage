# Доставка уведомлений 0.21

Отдельный процесс читает `local_alerts` в режиме read-only. Его задержки, повторы
и сетевые ошибки не блокируют монитор и UI. В этой поставке реальные сообщения
Telegram не отправлялись; адаптер проверен заглушками. Получатель ещё не настроен.

## Запуск без отправки

`Start-Delivery.cmd` запускает постоянную имитацию без HTTP-запросов. Она обрабатывает
только новые события после первого запуска, пишет текст в консоль и сохраняет
состояние в `data/delivery.sqlite3`. Ctrl+C завершает доставку, монитор продолжает работу.

```powershell
Set-Location G:\Arbitrage
# Проверка текста теста: не читает и не меняет курсор журнала, не отправляет наружу
.\.venv\Scripts\python.exe -m arbitrage.delivery --test
# Один проход либо постоянный просмотр с настройками
.\.venv\Scripts\python.exe -m arbitrage.delivery --config delivery.example.json
.\.venv\Scripts\python.exe -m arbitrage.delivery --config delivery.example.json --watch
```

Настройки можно скопировать из `delivery.example.json` в собственный JSON и передать
через `--config`. Токен и получатель в JSON не хранятся; неизвестные поля отклоняются.

| Поле | По умолчанию | Значение |
|---|---|---|
| events | opened, closed | Какие события доставлять |
| min_net_usdt | 0 | Строгий дополнительный порог условного net для opened, от 0 до 1 млрд |
| max_age_seconds | 60 | Предельный возраст события при попытке, 1–3600с |
| max_attempts | 5 | Общее число попыток, включая прерванные, 1–10 |
| poll_seconds | 2 | Интервал опроса и минимум между успешными сообщениями, 1–60с |

Этот порог доставки не меняет расчёты, SignalTracker, локальный журнал или счётчик UI.
Пропущенные по фильтру события после смены настроек повторно не отправляются.
`closed` доставляется только после успешного `opened` тому же получателю; поэтому
режим только `closed` полезен для уже объявленных этим процессом эпизодов.

## Подключение Telegram

Создайте бота через BotFather и подготовьте chat ID получателя, который разрешил
боту сообщения. Для личного чата сначала откройте бота и нажмите Start.
Токен задаётся переменной процесса `ARBITRAGE_TELEGRAM_BOT_TOKEN`, получатель —
`ARBITRAGE_TELEGRAM_CHAT_ID` (числовой ID или @имя канала). Не отправляйте токен в чат.

После локального задания переменных среды команды ниже **включают реальные сообщения**:

```powershell
# Только тест выбранному получателю, без обработки журнала
.\.venv\Scripts\python.exe -m arbitrage.delivery --send --test
# Рабочая доставка новых событий
.\.venv\Scripts\python.exe -m arbitrage.delivery --send --watch --config delivery.example.json
```

Без `--send` сетевых запросов нет, даже если переменные среды уже заданы.
С `--send` отсутствие/некорректный формат переменных завершает запуск с понятной ошибкой.
Переменные процесса доступны только этому окну и его дочерним процессам;
не сохраняйте секрет в исходниках или .cmd. Имитация и Telegram имеют разные курсоры,
поэтому проверка имитацией не отмечает события доставленными в Telegram.

Используется HTTPS POST `sendMessage`, обычный текст без HTML/Markdown,
таймаут 10с и запрет перенаправлений. Сетевые URL и текст ошибок Telegram
не выводятся и не сохраняются: токен входит в URL API. Протокол сверён с
[официальным Bot API](https://core.telegram.org/bots/api#sendmessage), обработка
лимита — с [ResponseParameters](https://core.telegram.org/bots/api#responseparameters).

## Перезапуск, сбои и границы гарантий

- При первом запуске для базы/получателя процесс запоминает конец журнала. Старый
  архив не рассылается. Отсутствующую базу он ожидает без создания файла.
- При обычном перезапуске продолжает с сохранённого курсора, пока события не устарели.
  Замена файла базы или смена получателя начинает новый курсор с конца. Откат курсора
  в том же файле базы останавливает процесс с ошибкой; выберите новый файл `--state`.
- `opened` не отправляется, если журнал уже содержит `closed` этого эпизода.
  Проверка перед отправкой не гарантирует неизменность рынка во время сети.
- В сообщении есть время UTC, event ID и пояснение monitor-only. Это сохранённое
  событие условной модели, а не обещание актуальной возможности или исполнения.
- Сетевые ошибки/таймауты/5xx повторяются с увеличением паузы до 60с. `429` соблюдает
  `retry_after` для всего получателя, включая перезапуск и смену ожидающего события.
  Неповторяемые ошибки и исчерпанные попытки помечаются failed; автоматического
  повтора failed нет. После исправления токена/прав нужно дождаться новых событий.
- Одновременно отправляется не более одного сообщения за проход. Неразрешённая
  ошибка останавливает обработку оставшейся порции до следующего прохода.
- Попытка записывается перед HTTP-запросом. После аварии незавершённая попытка
  ожидает 30с и учитывается в лимите. Если Telegram принял сообщение, а ответ
  потерялся, возможен повтор: sendMessage не предоставляет ключ идемпотентности.
  Одинаковый event ID помогает распознать его. Гарантия exactly-once не заявляется.
- Файл состояния содержит курсоры, результаты/число попыток и безопасные коды ошибок,
  без токена и текста сообщений. Записи результатов старше 30 дней удаляются при
  проходах; открытие старше этого срока не связывается с новым closed.
- ОС-блокировка не позволяет двум процессам использовать один `--state`.
  Для одного получателя используйте один процесс и один файл состояния. Другой
  файл состояния — независимый потребитель, блокировка между ними не действует.
- Обслуживание монитором основной базы не управляет размером базы доставки;
  после долгой работы её свободные SQLite-страницы могут остаться в файле.
