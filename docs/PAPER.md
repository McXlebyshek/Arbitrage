# Paper Trading 0.30

Первое ядро симуляции работает через `python -m arbitrage.paper`. Оно не соединяется
с биржами и не выставляет ордера. Источник — `data/latest.json`, который уже содержит
исходные стаканы расчётных кандидатов. Результаты сохраняются в отдельной
`data/paper.sqlite3`; основную рыночную SQLite нельзя использовать как paper-журнал.

## Команды

```powershell
Set-Location G:\Arbitrage
# Просмотр: отсутствующий файл не создаётся
.\.venv\Scripts\python.exe -m arbitrage.paper status
# Скопируйте точный id подтверждённой связки из economics.rows / signals.rows
.\.venv\Scripts\python.exe -m arbitrage.paper open --pair "PAIR_ID"
# POSITION_ID — id, возвращённый командой open
.\.venv\Scripts\python.exe -m arbitrage.paper mark --position "POSITION_ID"
.\.venv\Scripts\python.exe -m arbitrage.paper close --position "POSITION_ID"
```

Перед входом монитор должен работать, снимок — не старше 5с (будущее до 1с),
обе стороны глубины — не старше 3с относительно текущего времени. Также проверяются
исходное время, локальное получение, разрыв между ногами, идентичность контрактов,
размеры/шаги/лимиты и влияние на цену. Вход требует текущего confirmed-сигнала и
повторного расчёта положительного условного сценария на исходных данных снимка.
Отсутствие подтверждённой связки означает отказ во входе, без искусственного сигнала.

Исходное равное количество монет фиксируется. Выход LONG заполняет bids, SHORT — asks
для этого количества; текущий бюджет нового кандидата не пересчитывает позицию.
Тарифы выхода берутся из текущих метаданных с первоначальными fee-overrides.
Параметры размера/бюджета/допрасходов и ограничения фиксируются при входе.

Результат до funding:

`Q × (short_entry − long_entry + long_exit − short_exit) − entry_fees − exit_fees − extra_cost`.

Стаканное проскальзывание уже входит в VWAP, дополнительного вычета нет.
Суммарно резервируется до 1000 USDT на все открытые позиции: оба входных номинала,
входные комиссии и extra cost. Закрытие освобождает резерв. Это лимит модели, а не
симуляция маржинального счёта, ликвидации, ADL, резервов выходных комиссий или плеча.

## Что показывается честно

`pnl_before_funding_usdt` — расчётная переоценка или результат виртуального закрытия
до funding. В 0.23 отдельная команда `funding` сверяет исторические ставки из
рыночного архива. `funding_usdt` и итоговый `net_pnl_usdt` остаются **null**, пока
не покрыты обе истории и не предоставлены settlement mark prices всех событий.
Это итог симуляции по предоставленным ценам, не выписка реального счёта. Прогноз
`funding_events` из economics не переносится в выплаты симуляции.
Сумма закрытых результатов в status также помечена «до funding»; открытые позиции
в неё не входят. Это не доходность реального счёта и не завершённый Paper Trading.

Последняя успешная переоценка имеет `timestamp_ms` и может быть старой. `status`
читает журнал, не обновляет его котировки. При ошибке/нехватке глубины mark/close
отказывается от операции: позиция остаётся открытой, прежняя оценка сохраняется.
Закрытие требует более позднего снимка и обновления обеих ног после входа.
Время снимка и глубины не может идти назад относительно предыдущей оценки позиции;
новый вход той же связки должен быть позже её последнего закрытия.

## История и повторы

В журнале сохраняются позиции, события opened/marked/closed, исходные данные входа
и последующих оценок, SHA256 снимков, подтверждённый эпизод, комиссии и параметры.
Позиция и событие изменяются одной транзакцией с `BEGIN IMMEDIATE`.
Вход с тем же снимком/связкой возвращает прежнюю позицию, включая уже закрытую.
Один эпизод нельзя использовать для повторного входа; одновременно одна открытая
позиция на направленную связку. Mark с тем же снимком не добавляет событие,
повтор close возвращает сохранённый результат закрытой позиции.

Пока нет автоматической очистки paper-журнала: исходные данные могут занимать место.
Политика обслуживания рыночной базы к нему не применяется. Перезапуск CLI сохраняет
позиции. В 0.24 есть отдельный `Start-Paper-Watch.cmd` для автоматической переоценки;
watcher не открывает/закрывает позиции, правила — [PAPER_WATCH.md](PAPER_WATCH.md).
В 0.30 добавлен отдельный opt-in процесс автоматических правил: [PAPER_RULES.md](PAPER_RULES.md).

## Историческое воспроизведение

`--replay` явно отключает проверку возраста снимка относительно настенных часов,
сохраняя проверки времени/свежести относительно самого исторического снимка.
Replay и live используют разные журналы: смешивание режимов блокируется.

```powershell
.\.venv\Scripts\python.exe -m arbitrage.paper open --replay --database data/replay-paper.sqlite3 --snapshot data/saved.json --pair "PAIR_ID"
```

Для другого реестра можно передать `--registry PATH`. Исходные файлы могут содержать
искусственные данные; режим replay не утверждает их происхождение с бирж.

Воспроизводимая искусственная проверка CLI, с новой выходной папкой:

```powershell
.\.venv\Scripts\python.exe validate_paper_cycle.py --output data/paper-core-check-2
```
