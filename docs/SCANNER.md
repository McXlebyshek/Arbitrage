# Предварительный скринер 0.33

## Допуск инструментов

Явный реестр `arbitrage/instruments.json` содержит 120 контрактов 20 активов на шести основных биржах;
список и единицы — [REGISTRY.md](REGISTRY.md). Параметры сверены с живыми метаданными.
Ключ — exchange + native id. В записи заданы канонический актив, ожидаемый base,
число базовых единиц в единице котирования `price_units` и ожидаемый `contract_size`.
Это ограниченный реестр, а не автоматическое доказательство идентичности всех тикеров.
Правила индексов и риски расхождения контрактов автоматически не анализируются.
Добавлять новые соответствия нужно после проверки спецификаций площадок и единиц котирования.
Непроверенные тикеры не объединяются даже при одинаковом названии.

Проверяются активность, linear swap, quote/settle USDT, согласованность метаданных и котировки,
совпадение размера контракта с реестром. Изменение размера блокирует инструмент до пересмотра записи.
Registry можно передать явно: `--registry путь\к\instruments.json`.

Из котировок допускаются только native WS BBO со свежестью до 3 секунд и состоянием streaming.
Время перепроверяется на момент расчёта, сохранённая строка quality не принимается на веру.
Максимальная разница исходного времени двух ног — 1000 ms, меняется через `--max-skew-ms`.
Это допуск на рассогласование, а не доказательство одновременного исполнения.
MEXC ticker и самостоятельные REST-тикеры/стаканы в текущем скринере не допускаются.
С версии 0.4 MEXC разрешён через `ws_depth_verified`: локальный стакан после REST-инициализации
и успешного применения последовательных WS-обновлений. Внутри одной биржи допускаются
котировки только соединений со статусом streaming; сбой группы не исключает остальные группы.
После остановки либо обрыва соединения соответствующие текущие направления исчезают.

## Формулы

Пусть U — `price_units`, P — исходная цена, C — `contractSize` из метаданных.

- Цена за одну каноническую единицу: P / U.
- Базовых единиц в одном контракте: C × U.
- Edge входа: Bid_short − Ask_long.
- Спред входа в процентах: 100 × (Bid_short − Ask_long) / Ask_long.

`contractSize` меняет количество контрактов для заданной экспозиции, а не цену одной монеты.
Множитель единицы котирования U задаётся отдельно: для контракта на 1000 единиц токена он может
быть равен 1000, но только после явной проверки и записи в реестр. Механизм проверен синтетическим
тестом; в текущем реестре 20 активов U=1.

Для справочного общего номинала K (`--capital-usdt`, по умолчанию 1000, максимум 1000):

- Q = K / (Ask_long + Bid_short).
- Номиналы ног: Q × Ask_long и Q × Bid_short.
- Контрактов на каждой ноге: Q / (C × U) соответствующей биржи.

Базовое количество одинаковое, долларовые номиналы немного различаются, их сумма равна K.
Расчёт ведётся через Decimal; в JSON числа сериализуются в стандартный числовой формат.
Размеры названы `reference_*_unrounded`: шаг, минимум, пределы и ликвидность пока не проверены.
Они не являются готовыми размерами ордеров. Проверка фактического исполнения — этап экономики.

## Вывод и история

Для N допустимых бирж одного актива рассчитываются N × (N−1) направлений.
Оба направления сохраняются, отрицательные спреды не скрываются по умолчанию.
Строки сортируются по убыванию спреда; при равенстве используется стабильный id связки.
При BTC/ETH на шести биржах получается до 60 направлений; при 10 активах — до 300.
Фактическое число меньше при stale, рассогласовании времени или неполном охвате.

Параметры:

```powershell
# Две монеты, до 5 строк на экран, все направления в истории
.\.venv\Scripts\python.exe -m arbitrage --symbols BTC,ETH --interval 5
# Показать только спреды от 0,01%, до 10 строк на экран
.\.venv\Scripts\python.exe -m arbitrage --min-spread-pct 0.01 --top 10
# Не печатать строки таблицы; JSON и SQLite продолжают сохраняться
.\.venv\Scripts\python.exe -m arbitrage --top 0
```

`data/latest.json → scanner.rows` — текущие строки, `exclusions` — причины исключения котировок,
`skipped_pairs` — причины пропуска пар (например, source_time_skew), `evaluated_pairs` — число
направлений до фильтра по минимальному спреду, `displayed_pairs` — после фильтра.
`--top` влияет только на консоль. В SQLite таблица `scans` хранит полный результат расчёта
с исходными временами, версией реестра и признаками неполноты экономики. Запись выполняется
в одной транзакции с котировками. При штатной остановке сохраняется результат без текущих связок.
При чтении старого JSON возраст данных необходимо пересчитать.

У строк `classification=preliminary_price_spread`, `net_pnl_usdt=null`, `execution_verified=false`.
Funding, четыре комиссии, VWAP, округление количества, цены выхода и прочие расходы пока не учтены.
Это относится к сырому блоку scanner. С версии 0.6 отдельный блок economics проверяет
ограниченное число кандидатов; формулы и статус условной модели — в [ECONOMICS.md](ECONOMICS.md).
