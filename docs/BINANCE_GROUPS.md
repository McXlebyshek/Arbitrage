# Группировка Binance и повторные окна 0.37

`--binance-group-size` задаёт размер группы Binance отдельно от остальных бирж,
диапазон 1–20, по умолчанию 20. Фактический размер — минимум этой настройки и
общего `--group-size`. Настройка не меняет источник потока; его задаёт
`--binance-stream`. Значения сохраняются в config отчёта монитора.

```powershell
Set-Location G:\Arbitrage
.\Start-Monitor.cmd --binance-stream "depth5@500ms" --binance-group-size 20
# Изолированный полный прогон: новая папка и свободный порт
.\.venv\Scripts\python.exe validate_paper_live.py --directory data/binance-long-001 --duration 600 --port 8776 --rules --binance-stream "depth5@500ms" --binance-group-size 20
# Сравнение размеров 20/10/5 без рыночной SQLite
.\.venv\Scripts\python.exe validate_binance_groups.py --output data/binance-groups-001 --duration 180
```

Для 20 контрактов группы 20/10/5 требуют 1/2/4 соединения соответственно.
`--max-connections` остаётся пределом на биржу: при меньшей ёмкости появляются
omitted и полного охвата нет. Маленькая группа сама по себе не гарантирует
улучшения. Gate и MEXC сохраняют свои ограничения, если общий --group-size
пользователь не уменьшил отдельно.

Сравнительный стенд использует один поток depth5@500ms и один сохранённый набор
20 контрактов, три пула одновременно. После 30с прогрева сохраняет отдельные
30-секундные окна: samples, selected_sum/fresh_sum, доля свежих, переподключения,
устаревшие кадры и максимальную из наблюдавшихся недавних p95 источника.
Допустимая длительность — 90–600с. Метаданные взяты из сохранённого каталога;
актуальность REST в этом стенде не проверяется. Данные получаются трижды,
нагрузки истории/UI/economics нет, поэтому нужен отдельный полный прогон.
Собственные группы завершаются в finally, пользовательские процессы не управляются.

После завершения полного прогона поминутные окна рассчитываются чтением SQLite:

```powershell
.\.venv\Scripts\python.exe validate_freshness_windows.py --database data/binance-long-001/market.sqlite3 --run-report data/binance-long-001/monitor-report.json --output data/binance-long-001/windows.json
```

Число выбранных рынков может быть нулевым во время loading. Поэтому помимо доли
от текущего selected есть доля от наблюдавшейся пиковой ёмкости; она не скрывает
такой провал. Неполная последняя минута отмечена отдельно и не определяет минимум
по завершённым окнам. Пустая ёмкость — null, отсутствующие выборки не интерполируются.
Показатели основаны на сохранённых снимках, а не на непрерывном uptime; пик
выбранных рынков также не заменяет проверку полного охвата реестра/omitted.
Подробная методика: [DIAGNOSTICS.md](DIAGNOSTICS.md).

Ни размер группы, ни анализ окон не изменяют порог свежести 3с, timestamps,
подтверждения или paper-порог. Задержки и нестабильность предыдущих окон сохраняются
в отчётах; успешное новое окно их не отменяет.
Результаты: [BINANCE_GROUPS_CHECK.md](reports/BINANCE_GROUPS_CHECK.md).
