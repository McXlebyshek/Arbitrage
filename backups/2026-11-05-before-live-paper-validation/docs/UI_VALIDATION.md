# Проверка истории и совместной работы UI

С версии 0.18 доступны два воспроизводимых стенда. Оба работают с отдельными
выходными файлами; основной `data/market.sqlite3` в примерах не используется.

## Контролируемая большая история

```powershell
.\.venv\Scripts\python.exe validate_ui_history_load.py --source-db data/ui-live.sqlite3 --source-snapshot data/ui-live.json --database data/validation-month.sqlite3 --snapshot data/validation-month-fixture.json --report data/validation-month-report.json
```

Создаётся искусственная база: 30 направлений × 30 дней минутных точек, 200001
небольших сырых снимков, намеренно отсутствующая минута. Цены взяты как шаблоны
из исходной записи и повторены; **это не месяц рыночных наблюдений**.
Выходной JSON явно помечен `CONTROLLED SYNTHETIC BENCHMARK`.
Стенд не подключается к биржам и не предназначен для оценки доходности.

Проверяются индексированный план SQL, точки в старых суточных окнах, пропуск,
отсутствие действующих подтверждений, целостность SQLite и HTTP-задержки при 4 клиентах.
Размер по умолчанию — около 600 МиБ; параметры ограничены 30 днями/30 направлениями.
Повторный запуск создания откажется перезаписывать файлы. Чтобы повторить только
чтение уже помеченного стенда, добавьте `--reuse-fixture` (сначала сверяется размерность).

## Совместный публичный прогон

```powershell
.\.venv\Scripts\python.exe validate_ui_soak.py --directory data/validation-ui-run --report data/validation-ui-run-report.json --duration 600 --port 8769
# Для существующего архива funding можно добавить --seed-db data/ui-live.sqlite3
```

Создаются отдельные монитор и loopback UI. Каждые 2 секунды клиент получает таблицу
и одну из карточек, меняет периоды funding и иногда запрашивает прошлое окно графика.
Проверяются времена наблюдений, текущие подтверждения, доступность HTTP и переход
в непустой архив после остановки. Допустимый 404 учитывается отдельно: связка может
исчезнуть из пригодного снимка между двумя запросами.

`--directory` должна быть новой папкой. Опциональная исходная база копируется через
SQLite Backup API, её записи не изменяются. Сбор использует публичные API без ключей
и реальных ордеров. Автоматическое обслуживание остаётся включённым с периодом 60с.

`--duration` допускает 30–86400 секунд; это запуск текущей команды, не установленная
служба и не расписание. Созданные процессы завершаются самим стендом.
`--keep-ui-seconds 120` оставляет UI для просмотра архива ещё на две минуты после
проверки, затем закрывает его. Журналы и отчёт монитора сохраняются в новой папке.

Итог `passed` относится к проверке UI. `producer_exit_code=1` может означать неполную
свежесть последней выборки: причины и охват смотрите в `monitor-report.json`.
Десятиминутный прогон не подтверждает круглосуточную устойчивость.
