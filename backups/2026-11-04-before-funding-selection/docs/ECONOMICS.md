# Условная экономика связок 0.6

Блок `economics` дополняет сырой `scanner`. Он не выдаёт результат уже совершённой сделки:
`net_pnl_usdt=null`, `execution_verified=false`. Полный расчёт называется `scenario_estimated`.
Его условия и исходные данные сохраняются вместе с результатом.

## Сбор данных

По умолчанию подробно проверяются три лучших направления по сырому спреду (`--economics-pairs 3`).
Это ограниченный отбор, а не поиск всех наиболее выгодных funding-связок. Значение 0 отключает
модуль, максимум — 10 направлений. У каждой биржи независимые задачи истории/ставок и глубины:
медленная загрузка каталога или стакана одной биржи не задерживает опрос остальных.

- Стакан: публичный REST, до 20 уровней. Объёмы контрактов переводятся в одинаковый базовый актив.
- Возраст стакана — не более 3 секунд, разница времён двух бирж — не больше `--max-skew-ms`.
- Ставки funding и оборот обновляются по требованию не чаще раза в минуту на инструмент;
  возраст допуска — до 120 секунд. Ошибки не превращаются в нулевые значения.
- История запрашивается за 48 часов, до 100 записей, повторно через 15 минут.
  Для сценария нужен проверяемый ряд не менее 24 часов, без пропусков относительно интервала.
- У Binance интервал может отсутствовать в unified-ответе. Если история регулярная,
  он выводится из неё с меткой `inferred_from_history`, а не объявляется текущим правилом биржи.
- Суточный оборот — минимум 1 млн USDT на обеих биржах. Если unified quoteVolume OKX отсутствует,
  используется нижняя граница оборота: сумма `volCcyQuote` 1H-свечей, начавшихся внутри последних 24 часов.
  Самый старый частичный час не добавляется, объём базовой монеты не умножается на last price.
- Котировки REST не заменяют WS-сигнал. Подробный результат отображается только для направлений,
  которые в текущем WS-снимке прошли проверки свежести и идентичности.

## Размер и ликвидность

Для каждой ноги определяются размер контракта и шаг количества CCXT. Поддерживаются TICK_SIZE
и DECIMAL_PLACES; неизвестный режим блокирует расчёт. Строится общий шаг базового количества
через рациональное НОК, затем выбирается одинаковое Q, допустимое для обеих ног.
Количество не округляется независимо на двух биржах: это нарушило бы равенство экспозиции.

Проверяются четыре прохода по текущим стаканам: покупка LONG, продажа SHORT, продажа LONG
при немедленном закрытии и покупка SHORT при немедленном закрытии. Недостаточная глубина
или превышение влияния цены уменьшает допустимый размер либо блокирует расчёт.

- По умолчанию влияние каждого исполнения — до 0,10% (`--max-impact-pct`).
- Размер должен использовать минимум 90% бюджета номиналом (`--min-budget-utilization`).
- Бюджет `--capital-usdt` не больше 1000: сумма номиналов входа, оценочных комиссий входа
  и `--extra-cost-usdt` должна помещаться в него.
- Проверяются шаги, минимумы и максимумы количества, market-количества и номинала.

Это предварительная допустимость количества. Баланс, маржа, liquidation/ADL, ограничения аккаунта,
цены срабатывания ордерных защит и доступность торговли не проверяются. Реальные ордера не создаются.

## Комиссии

Учитываются taker-комиссии всех четырёх исполнений. По умолчанию берётся публичная оценка CCXT;
для Gate при наличии используется `info.taker_fee_rate` спецификации контракта. Это не тариф
пользовательского аккаунта: VIP, акции и API-тарифы могут отличаться. Источник записывается в fee_sources.

Можно явно задать собственные предположения: JSON-словарь `exchange_id → fractional_rate`.
Например, `0.0005` означает 0,05%, а не 0,0005%. Файл [fees.example.json](../examples/fees.example.json)
содержит только одинаковые демонстрационные ставки; это не проверенные тарифы бирж.
Отсутствующие в профиле биржи продолжают использовать публичную оценку.
Даже с профилем `account_fees_verified=false`: приложение не подтверждает его через аккаунт.

## Формулы и сценарии

Все суммы рассчитываются через Decimal. VWAP уже включает глубину и проскальзывание;
повторного вычитания той же разницы с лучшей ценой нет.

Пусть L_buy/S_sell — VWAP входа, L_sell/S_buy — VWAP немедленного закрытия.

- Edge входа: Q × (S_sell − L_buy).
- Price PnL немедленного закрытия: Q × [(S_sell − L_buy) + (L_sell − S_buy)].
- Результат немедленного закрытия до funding: Price PnL − четыре комиссии − дополнительные расходы.

Для будущего схождения используется явное допущение: обе позиции закрываются по одной
цене, равной среднему текущих midpoint двух бирж. Закрывающие комиссии учтены, будущая
глубина и дополнительное проскальзывание выхода неизвестны. Поэтому это сценарий, а не
исполнимая прибыль. Отдельно показан необходимый для безубыточности edge выхода.

Funding рассчитывается по отдельным событиям каждой биржи в горизонте `--hold-hours` (по умолчанию 8).
Для LONG cashflow = −Q × reference_price × rate; для SHORT знак положительный.
Ближайший платёж берётся из fundingTimestamp, соответствующего fundingRate.
nextFundingRate не подставляется вместо ближайшей ставки: в unified-структуре это может быть другой период.

Последующие события повторяют текущие ставку, интервал и midpoint. Это явное предположение
`constant_current_rate_interval_and_midpoint_not_actual_cashflows`: будущие ставки и mark price могут измениться.
Просроченное расписание не продлевается автоматически. Если ставка, интервал или история неизвестны,
общая сумма с funding не выдаётся. Горизонт 0 означает отсутствие будущих начислений в модели.

## Статусы и хранение

- `blocked`: не прошли данные, размер, глубина, оборот или комиссии; reasons содержит причину.
- `entry_checked`: размер/стакан/комиссии рассчитаны, но funding-сценарий неполон.
- `scenario_estimated`: есть условная оценка схождения и funding при указанных предположениях.

`data/latest.json → economics` и таблица SQLite `economics` содержат результаты, policy и исходные
стаканы, параметры контрактов, наблюдения оборота, funding/историю. Отрицательные результаты сохраняются.
При остановке текущие строки очищаются, история остаётся. Повторная публикация старого стакана
не обновляет его время. Ошибка нового запроса удаляет предыдущий кэш этого стакана.

```powershell
# Рабочий режим: 3 кандидата, горизонт funding 8 часов
.\.venv\Scripts\python.exe -m arbitrage --interval 2 --economics-pairs 3
# Пользовательский профиль предположений о комиссиях
.\.venv\Scripts\python.exe -m arbitrage --fees-profile .\my-fees.json --hold-hours 4
# Только прежний сырой скринер
.\.venv\Scripts\python.exe -m arbitrage --economics-pairs 0
```

Ограничения следующей итерации: более широкий отбор по funding, уменьшение доли ожидающих/просроченных
кандидатных стаканов, история 7/30 дней и подтверждение сигналов несколькими обновлениями.

Источники: [CCXT contracts, precision, funding](https://github.com/ccxt/ccxt/wiki/manual),
[OKX candles / volCcyQuote](https://www.okx.com/docs-v5/en/#order-book-trading-market-data-get-candlesticks).
