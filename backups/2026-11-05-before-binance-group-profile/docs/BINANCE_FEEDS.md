# Выбираемые потоки Binance 0.36

Параметр `--binance-stream` задаёт источник предварительных bid/ask Binance.
По умолчанию остаётся `bookTicker`. Альтернативы доступны для проверки;
полная рыночная устойчивость ни одного режима пока не подтверждена.

| Значение | Подключение / topic |
|---|---|
| bookTicker | /public/ws, `<symbol>@bookTicker` |
| bookTicker-combined | /public/stream, `<symbol>@bookTicker` |
| depth5@100ms | /public/stream, `<symbol>@depth5@100ms` |
| depth5@500ms | /public/stream, `<symbol>@depth5@500ms` |

```powershell
Set-Location G:\Arbitrage
.\Start-Monitor.cmd --binance-stream "depth5@500ms"
# Изолированная проверка пяти процессов в новой папке
.\.venv\Scripts\python.exe validate_paper_live.py --directory data/binance-depth-run-001 --duration 180 --port 8776 --rules --binance-stream "depth5@500ms"
# Одновременное сравнение четырёх режимов без рыночной SQLite
.\.venv\Scripts\python.exe validate_binance_streams.py --output data/binance-comparison-001 --duration 120
```

Последний стенд использует проверенные 20 контрактов из сохранённого каталога
`docs/reports/REGISTRY_V033_CATALOG.json`; данные получаются четырежды на четырёх
сокетах. В нём нет нагрузки полного монитора и повторной проверки актуальности
каталога через REST. Дочерние группы закрываются в finally; пользовательские
процессы не управляются. `--duration` допускает 30–300с, прогрев 20с.

## Проверки протокола

Combined-режим требует оболочку stream/data. Topic должен в точности совпадать
с выбранным режимом и symbol внутри сообщения, а инструмент — находиться в
назначенной группе. Обычный `@depth@100ms` не принимается за `@depth5@100ms`.
Тип инструмента st=2 (COIN-M) отвергается, отсутствие поля допускается для старого
формата; при наличии ожидается st=1.

Partial depth интерпретируется только в контексте выбранного partial-topic:
из полученных верхних уровней берутся лучшие bid/ask, снимок заменяет предыдущую
котировку целиком. Нет накопления или слияния incremental diff. Проверяются
не более 5 уровней на сторону, их порядок и положительные цены/размеры.
Пустая или нулевая сторона не заполняется старой ценой или нижним уровнем.
Нет обещания полного покрытия стакана или доступного размера исполнения.

В combined-режимах u — целый неотрицательный update id. Повторный/обратный id
игнорируется и не обновляет получение котировки. Пропуски id допустимы для
отдельных снимков верхних уровней; локальный полный стакан из них не строится.
При новом соединении котировки и id очищаются, подписка выполняется заново.
Проверка обратного source timestamp также остаётся общей для потоков.

Время источника — T; при отсутствии T используется E. E и локальное получение используются
в диагностике отдельно и не заменяют T ради свежести. Порог 3с, watchdog и
исключение disconnected сохраняются. Неизвестный/старый timestamp не становится
валидным от правильного topic или частого получения сообщений.

Экономика получает глубокие стаканы прежним отдельным REST-сбором. Пять уровней
скринера не подставляются вместо четырёх VWAP, ликвидности или paper-исполнения.
Сигналы и paper-порог не изменялись. Выбранный режим виден в config отчёта
монитора и connection_statuses; уже работающий процесс требует перезапуска.
