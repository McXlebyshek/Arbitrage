# Локальный интерфейс 0.17

В `G:\Arbitrage` откройте `Start-Monitor.cmd`, затем `Start-UI.cmd`.
Первое окно непрерывно собирает данные, второе открывает http://127.0.0.1:8765/.
Остановка каждого процесса — Ctrl+C в его окне. UI сам монитор не запускает.

Эквивалент запуска интерфейса из PowerShell:

```powershell
Set-Location G:\Arbitrage
.\.venv\Scripts\python.exe -m arbitrage.ui --open-browser
# Отдельно сохранённый двухминутный публичный прогон, только архив:
.\.venv\Scripts\python.exe -m arbitrage.ui --snapshot data/ui-live.json --database data/ui-live.sqlite3 --open-browser
```

По умолчанию используются `data/latest.json` и `data/market.sqlite3`.
Можно передать `--snapshot`, `--database`, `--registry` и `--port` (1024–65535).
При собственном реестре у монитора и UI должен быть одинаковый `--registry`.
Сервер слушает только 127.0.0.1; SQLite открывается в режиме read-only.
Статика поставляется с проектом, внешних CDN нет. UI не имеет методов отправки ордеров
или изменения настроек сбора, не требует биржевых ключей и не публикуется в интернете.

## Таблица и карточка

Режимы: лучшая связка каждого актива, все направления, выбранные расчёты экономики.
Доступны поиск, выбор обеих бирж, пороги спреда/условного net, готовность и сортировка.
Звезда сохраняет конкретное направление LONG/SHORT. Избранное и колонки хранятся
в localStorage браузера. Без сохранённых настроек при ширине меньше 1100 px три
дополнительные колонки скрыты; их можно включить. Таблица прокручивается по горизонтали,
карточки бирж в узком окне располагаются вертикально.

В 0.16 над карточками появились выбор LONG/SHORT и кнопка разворота.
Доступны только направления того же актива из текущего снимка; противоположная нога
сохраняется, одна биржа на обеих сторонах не предлагается. Фильтры таблицы на этот
список не влияют. Выбор меняет просматриваемую связку, не отбор глубины монитором.
У новой связки может не быть детальной экономики: прежняя оценка не переносится.
Выбранная вкладка графика и диапазон при смене ног сохраняются; масштаб сбрасывается.

Нажатие строки открывает две ноги, bid/ask, funding, доступный оборот,
расчёт экономики, причины блокировки и последние события. Escape закрывает карточку,
`/` переводит фокус в поиск. При открытии другой связки старые значения очищаются.
Возраст данных обновляется каждую секунду; таблица опрашивается раз в 2 секунды,
открытая карточка — дополнительно раз в 9 секунд. Даты отображаются в Europe/Kyiv.

## Значения

- Вход, % = `100 × (SHORT bid − LONG ask) / LONG ask` — сырой исполнимый спред BBO.
- Выход, % = `100 × (LONG bid − SHORT ask) / SHORT ask` — обратное направление,
  с тем же знаменателем, что у соответствующей обратной строки сканера.
- Цены нормализованы к одной базовой единице по реестру, включая множители контрактов.
- Funding каждой ноги показан со своим периодом и временем следующего начисления.
  Разные периоды не вычитаются напрямую. «F net 24ч» — сумма наблюдавшихся ставок SHORT
  минус сумма ставок LONG за покрытое окно 24ч, при условном одинаковом номинале.
  Это сравнение истории ставок, не фактические денежные начисления позиции.
- Условный net берётся из модели экономики: общие размер/бюджет, VWAP, четыре комиссии
  и funding-сценарий. Будущая цена выхода и тариф аккаунта не подтверждены.
- Неизвестное обозначается прочерком. Нулём оно не заменяется; APR и OI пока отсутствуют.

## Свежесть и архив

Живой снимок должен быть не старше 5 секунд. Для действующей связки обе котировки
проверяются по исходному и локальному времени: до 3 секунд, допуск будущего времени 1 секунда.
Текущее подтверждение дополнительно требует глубины обеих ног до 3 секунд и,
при ненулевом funding-горизонте, funding до 120 секунд. Клиент пересчитывает свежесть
между ответами сервера. Это допуск данных модели, не подтверждение реального исполнения.

Если свежих строк нет или монитор остановлен, UI может показать последний непустой
снимок из последних 50 записей сканера. Он явно обозначен архивом; текущие подтверждения
сняты, отсчёт funding относится к времени снимка. Отсутствие истории даёт пустое состояние.
Ошибка чтения текущего JSON допускает показ архива с пояснением.

## Графики и оставшаяся работа

Вкладки: сырой спред входа/выхода, цены входа обеих ног, исторические начисления funding.
Нижняя панель синхронизирована с текущими наблюдениями ставок. Курсор показывает значения,
ползунок показывает последние 20–100% длительности окна; кнопка сброса возвращает весь набор.
Пропуски более 10 секунд между сырыми наблюдениями не соединяются линией.

Окно 1 минута читает до 300 подробных снимков. В 0.15 окна 15 мин / 1ч / 6ч / 24ч
используют отдельные минутные сводки `chart_rollups`, индексированные по связке и времени.
Они охватывают весь выбранный диапазон доступной истории, а не только последние 300 снимков.
Точка — последнее реальное наблюдение минуты с его временем; вертикальный отрезок
показывает min/max. Сохраняются исходные нормализованные цены, прямой/обратный спред,
число снимков и границы наблюдений. Неизвестный обратный спред остаётся пустым.
Нижняя панель читает минутные наблюдения funding, включая собственный период ставки;
при изменении периода линия разрывается. Между минутными точками разрыв более 90с
не соединяется. Линии лишь соединяют сохранённые точки, промежуточные наблюдения не создаются.
Наличие точки не означает непрерывного покрытия всей минуты; min/max относится
ко всей сохранённой минуте, включая её часть до левой границы выбранного окна.

Сводки обновляются вместе с публикацией в одной транзакции; контрольная позиция
не позволяет повторно учитывать обработанные снимки. Отставание сводок явно показано в UI.
Автоматическая очистка ожидает завершения агрегации и хранит сводки по `--summary-history-days`
(по умолчанию 30 дней), архивируя удаляемые строки по действующей политике.
Ручная очистка сначала агрегирует доступные старые снимки. Абсолютного предела размера базы нет.

Старая база без таблицы сводок продолжает показывать до 300 исходных снимков с предупреждением.
Для её полного заполнения остановите монитор и выполните (повторный запуск идемпотентен):

```powershell
.\.venv\Scripts\python.exe -m arbitrage.chart_history --database data/market.sqlite3
```

Команда использует блокировку монитора и обрабатывает по 25 снимков за транзакцию.
UI остаётся read-only. При обычном запуске монитора старые записи также постепенно агрегируются;
из уже удалённых сырых записей минутные цены восстановить невозможно.
Сводки сохраняют только фактически записанные сканером направления (включая его фильтры).

Фактические события funding за последние 30 дней читаются отдельно из импортированной
истории (до 1000 событий на ногу); новая база без импорта не содержит этого ряда.

## Табличное сравнение funding

Под графиком доступны LONG, SHORT и сравнение, периоды 24ч/3д/7д/14д/28д/30д.
Источником служит импортированная история funding из SQLite; UI не обращается к биржам.
События объединяются по фактическому времени, у каждой ноги остаётся собственный ритм.
Показаны ставки, накопленные суммы имеющихся записей и их разница SHORT − LONG.
Суммы считаются от начала общего окна; таблица выводится от новых записей к старым.
50 строк загружаются сразу, кнопка показывает следующие 50.

Полная разница периода показана только при проверенном наблюдаемом покрытии обеих ног:
левая опорная запись, регулярный ритм и допустимый возраст последнего события,
без ошибки импорта/усечения. При неполной истории полная разница — прочерк;
суммы имеющихся записей остаются видны с пометкой. Пустые события не заменяются нулями.
Лимит — 1000 последних событий на ногу; при его достижении с усечением есть предупреждение.
Это суммы ставок при равном условном номинале, не начисления и не результат аккаунта.
Время правой границы для архива соответствует сохранённому снимку, для live — времени запроса.

## Навигация и настройки графиков 0.17

Кнопки «Раньше»/«Позже» сдвигают окно на 80% видимой длительности, «К последним»
возвращает конец доступных данных и масштаб 100%. В live на конце график следует
за обновлениями; в просмотре прошлого правая граница фиксирована. Архив остаётся архивом.
Текущая карточка и таблица сравнения funding продолжают относиться к своему времени:
прокрутка меняет только графики. У окна есть явная подпись дат и времени Киева.
Смена вкладки, диапазона или ног возвращает конец графика к последним данным.

Ползунок 20–100% меняет длительность окна, а не число точек. У вкладки funding
фиксированный исходный период 30 дней (масштаб 20% показывает 6 дней);
селектор минут на этой вкладке скрыт. Поле API `end_ms` задаёт правую границу,
будущее ограничено текущим временем данных. Пустые интервалы не заполняются.
Левая граница определяется доступной историей базы; выбранная связка может иметь пропуски.

Курсор показывает ближайшее реальное наблюдение и его время: проценты спреда,
цены LONG ask/SHORT bid либо исторические ставки отдельно по ногам. Допустимая близость:
10с для raw, 90с для минут, 6ч для исторического funding. Вне этого расстояния
показано «нет записи рядом». Числа между наблюдениями не вычисляются.

Настройки включают высоту обоих графиков, min/max минуты, сетку и нижнюю панель funding;
они сохраняются в localStorage (`arbitrage.charts`), есть сброс к исходным значениям.
Кнопка разворачивания занимает графиками окно приложения, повторное нажатие сворачивает.
Escape сначала закрывает настройки, затем развёрнутый просмотр, затем карточку.
При фокусе внутри графиков: ←/→ — навигация, E — последние данные, F — развернуть/свернуть.
Поля ввода и селекторы сохраняют собственные клавиши управления.

Проверки: [CHART_NAVIGATION_CHECK.md](reports/CHART_NAVIGATION_CHECK.md).
JavaScript-модель можно проверить без сторонних пакетов: `node tests/chart-model.test.cjs`.
