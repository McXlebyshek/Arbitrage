# Панель Paper Trading 0.25

После обновления перезапустите `Start-UI.cmd` и обновите страницу.
Кнопка **Paper** в шапке открывает отдельную панель виртуального портфеля.
Она ничего не записывает в базы и не открывает/закрывает позиции.

По умолчанию UI читает `paper.sqlite3` рядом с рыночной базой. Для другого журнала:

```powershell
.\.venv\Scripts\python.exe -m arbitrage.ui --paper-database data/custom-paper.sqlite3
```

## Что показано

- Количество открытых/закрытых позиций и общий резерв открытых.
- Сумма закрытых результатов **до funding**.
- Общий итог закрытых только если итоговый net известен у каждой закрытой позиции.
  Если хотя бы один неизвестен, показано «Не рассчитан», а не частичная сумма или ноль.
- Число закрытий с полным funding; плюсовые, минусовые и нулевые результаты только
  среди них. Открытые позиции в статистику закрытых не входят.
- По позиции: направление, исходное базовое количество, комиссии входа/выхода,
  результат до funding, итог симуляции, состояние funding и время оценки.

Итог funding использует предоставленные settlement mark prices; их происхождение
независимо не проверено. Это paper-симуляция с оценочными тарифами, не реальный счёт.
Денежные значения в UI округляются до двух знаков; CLI сохраняет полные числа.
Результат до funding не заменяет итог с funding.

Есть фильтры открытых/закрытых/всех и страницы по 25 позиций, новые записи сверху.
Сводка относится ко всему журналу, а не только странице/фильтру.
Если направление есть в текущей таблице scanner, кнопка открывает обычную карточку;
если его нет, это явно написано. Карточка scanner может быть архивной — её собственная
пометка сохраняется и не превращает paper-запись в действующий сигнал.

## Свежесть и ошибки

У открытой live-позиции свежая оценка требует возраста публикации до 5с, обоих
источников глубины до 3с и допуска будущего времени до 1с. Надпись меняется по
времени между опросами; передача запроса не продлевает срок годности данных.
Закрытые записи являются историей, replay никогда не показывается как свежий live.
Режим replay выделен отдельной строкой над списком.

Панель опрашивает API раз в 5с, пока открыта и вкладка видима. При ошибке остаётся
последний полученный ответ с явным предупреждением; свежая оценка при ошибке не
показывается. Пустой/отсутствующий журнал не создаёт файл и имеет собственное
сообщение. Фильтр/страница обновляют список с начала; обычный опрос сохраняет прокрутку.

Список обновляется по ID позиций без полной замены DOM. Escape закрывает панель и
возвращает фокус на Paper, Tab остаётся внутри панели; основной экран на время
открытия недоступен для фокуса. На мобильной ширине сводка занимает две колонки.

## Read-only API

`GET /api/paper?state=open&limit=25&offset=0` возвращает согласованную сводку и
ограниченную страницу из одного read-only снимка SQLite. `state`: open/closed/all,
limit 1–100, offset 0–1 000 000. При уходе страницы за конец offset сбрасывается на 0.
POST не поддерживается (405), неверные параметры дают 400, недоступная база — 503.

В ответе только поля отображения: исходные стаканы, подтверждения и массивы
funding-событий не передаются. Агрегация использует Decimal; сводка проходит весь
журнал, поэтому полная производительность на многомесячном paper-архиве ещё не измерена.
API и статус UI не выполняют переоценку; для неё нужен `Start-Paper-Watch.cmd`.
