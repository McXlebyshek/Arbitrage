# Загрузка settlement mark prices 0.26

Добавлен первый точный публичный адаптер: **Binance USD-M**. Endpoint
[Get Funding Rate History](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Get-Funding-Rate-History)
возвращает `markPrice`, связанную с конкретным funding-начислением.
Свечи mark price, last price и текущая цена в этот расчёт не подставляются.

```powershell
Set-Location G:\Arbitrage
.\.venv\Scripts\python.exe -m arbitrage.paper funding --position "POSITION_ID" --fetch-prices
# Цены другой ноги можно дать отдельным файлом; они имеют приоритет
.\.venv\Scripts\python.exe -m arbitrage.paper funding --position "POSITION_ID" --fetch-prices --funding-prices data/other-leg-marks.json
# Повторно запросить автоматические цены вместо последнего сохранённого кэша
.\.venv\Scripts\python.exe -m arbitrage.paper funding --position "POSITION_ID" --fetch-prices --refresh-prices
```

Для replay добавьте `--replay --database data/replay-paper.sqlite3`; при другом реестре
передайте `--registry`. Это один явный запуск, не фоновая задача. Без `--fetch-prices`
прежняя сверка остаётся офлайн. Флаги загрузки разрешены только для действия funding.

## Последовательность

1. Читается конкретная позиция и проверяется replay/live режим и совпадение её
   привязок с текущим реестром. Файл ledger читается mode=ro.
2. Из локального архива выбираются состоявшиеся funding-события окна позиции.
   Архив не обновляется автоматически: ставки/покрытие по-прежнему должны быть доступны.
3. Используются явно предоставленные цены. Из последней сверки можно переиспользовать
   скачанную Binance-цену с тем же инструментом, временем и ставкой.
4. Только для недостающих Binance-цен выполняется HTTPS GET к фиксированному
   `https://fapi.binance.com/fapi/v1/fundingRate` с нативным symbol/startTime/endTime.
5. Проверяются symbol, точное fundingTime, Regular rateType, положительная конечная
   markPrice и совпадение fundingRate с архивом. Конфликтующая/повреждённая страница
   не даёт новых цен; отсутствие markPrice остаётся пропуском.
6. Обычная PaperLedger.funding заново сверяет окно и атомарно сохраняет результаты.
   Цены сохраняются в её событиях; исходная рыночная база не изменяется.

Автоматическая цена несёт `settled_rate`. Если архив исправлен между загрузкой и
сверкой, несовпадение ставки блокирует эту цену и оставляет net=null. Это также
доступное необязательное поле для вручную предоставленного файла цен.
Совпадение инструмента/поля API проверено, но выплаты счёта и происхождение
переданного пользователем файла не верифицируются: execution_verified=false,
price_evidence_verified=false сохраняются.

## Кэш, ограничения и ошибки

Кэш — только цены последнего сохранённого funding-расчёта позиции из этого адаптера.
Смена ставки требует запроса заново. `--refresh-prices` игнорирует этот кэш;
явно переданный файл всё равно имеет приоритет. Исправление только цены на стороне
API при неизменной ставке без refresh автоматически не обнаруживается.
Новая переоценка сбрасывает funding и этот кэш согласно существующей модели.

Один запрос — максимум 1000 строк, максимум 3 страницы/2000 требуемых событий на
контракт. Курсор двигается за максимальное полученное время, между страницами
пауза 0.75с. Таймаут 15с, перенаправления запрещены. При HTTP 429, запрете доступа,
ошибке сети/данных повторов внутри запуска нет; причина возвращается в отчёте.
Этот небольшой лимит не заменяет общий IP-бюджет Binance, разделяемый с другими
процессами. При ограничении повторный запуск нужно отложить.

Цены с успешно проверенных прежних страниц сохраняются в частичном результате.
Оставшиеся отсутствующие цены/история не превращаются в ноль: итог только при
полном покрытии ставок и цен обеих ног. Сверка может записать partial, если загрузка
не удалась. `price_download` в выводе CLI показывает запросы, кэш, downloaded,
unsupported, missing и error. В SQLite остаются использованные данные и источники,
а не отдельный сетевой журнал `price_download`.

## Остальные биржи

Адаптеры точных settlement marks для Bybit, OKX, Bitget, Gate и MEXC пока не
реализованы. Проверенные методы истории ставок
[Bybit](https://bybit-exchange.github.io/docs/v5/market/history-fund-rate) и
[OKX](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-funding-rate-history)
не содержат аналогичного поля mark price. Это не утверждение, что подходящих
источников у этих площадок вообще нет. Текущий загрузчик помечает их
`exact_settlement_mark_adapter_unavailable` и не делает для них сетевых запросов.
Они могут быть дополнены ручным файлом цен; без этого итог останется неполным.

## Проверки

12 новых офлайн-тестов включают строгий разбор ответа, пагинацию/лимит, ошибки,
сочетание с ручной ногой, кэш/refresh, исправление ставки до/после загрузки и CLI.
Публичный read-only прогон BTCUSDT выполнил два GET: исходная история и запрос
через адаптер, цена совпала без округления. Никаких ордеров/позиций для него не создавалось.

