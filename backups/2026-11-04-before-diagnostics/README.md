# Arbitrage Monitor 0.4

Локальный проект из диалога «Исследование криптоарбитража».
Рынок: активные линейные USDT perpetuals. Режим: monitor only.
Расчётный бюджет дальнейшей симуляции: до $1 000 совокупно, плечо 1x.
Ключи бирж не нужны. Методов выставления ордеров в проекте нет.

## Что работает

- Реестр Binance USD-M, Bybit, OKX, Bitget, Gate и MEXC через публичный REST API CCXT.
- Полный список подходящих контрактов; по умолчанию мониторинг 10 активов из явного реестра.
- Bid/ask, объём в USDT при наличии, размер контракта, исходное и локальное время.
- Проверка отсутствующих цен, пересечённого стакана и возраста данных.
- История снимков в SQLite, последний результат в JSON, состояние каждой биржи.
- Независимые native WebSocket-потоки: Binance bookTicker, Bybit orderbook.1,
  OKX bbo-tbt, Bitget v3 books1, Gate book_ticker; MEXC — синхронизированный локальный стакан.
- Heartbeat, обнаружение отсутствия данных, повторные подключения с паузой до 30 секунд.
- Отключённые котировки сразу исключаются; после подключения требуется новый снимок.
- Предварительный скринер LONG/SHORT для BTC, ETH, SOL, XRP, ADA, DOGE, LINK, LTC, AVAX и DOT.
- Нормализация цен и размеров контрактов, контроль временного разрыва котировок, объяснения исключений.
- Сортируемая по спреду консольная таблица; все рассчитанные строки и причины исключений — в JSON и SQLite.
- Группы WS-соединений, общий ограничитель подключений каждой биржи и бюджет REST-снимков MEXC.
- Периодическое обновление метаданных и явный учёт рынков за пределами заданной ёмкости.

Это предварительный скринер ценовых спредов. Funding, комиссии, глубина и допустимый размер
ордера ещё не учитываются, поэтому положительный спред не является подтверждённой прибыльной связкой.
По умолчанию запускается непрерывный WebSocket-монитор.
`--symbols REGISTERED` (по умолчанию) выбирает 10 активов реестра; можно задать список или ALL.
ALL означает запрос всех активных рынков в пределах ёмкости, а не обещание полного покрытия.
По умолчанию максимум 8 соединений на биржу, до 20 рынков в одном соединении (MEXC — до 5).
MEXC дополнительно ограничен 20 локальными стаканами. За пределами лимитов рынки учитываются
в `omitted_markets`; сначала отбираются инструменты из реестра. Для ALL начальные лимиты не покрывают весь рынок.
MEXC использует REST-снимок и последовательные WS-диапазоны begin/end. Пропуск версии,
пересечение стакана или выход за границы снимка исключает котировку до повторной синхронизации.
Старый ticker MEXC по-прежнему не считается подтверждённым источником времени стакана.
Поддержка адаптера не означает, что доступность API уже подтверждена.
В REST `state=ok` означает успешный запрос, в WS `streaming` — поступление данных;
пригодность котировок отдельно показана в `quality` и `usable_quotes`.
Источник времени ticker может отражать обновление тикера, а не конкретно bid/ask.
Поэтому даже `quality=ok` не заменяет проверку свежести стакана перед расчётом сделки.
Неизвестные значения сохраняются как `null`, без подстановки last price.

## Запуск в PowerShell

```powershell
Set-Location G:\Arbitrage
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m arbitrage
```

```powershell
# WS: снимок раз в секунду, Ctrl+C завершает работу
.\.venv\Scripts\python.exe -m arbitrage
# Проверка WS в течение 60 секунд, сохранение каждые 5 секунд
.\.venv\Scripts\python.exe -m arbitrage --duration 60 --interval 5
# Группы по 4 рынка: по три соединения на биржу для начального реестра
.\.venv\Scripts\python.exe -m arbitrage --group-size 4 --interval 5
# Ограниченная проверка ALL: до 40 рынков на BBO-биржу и 10 стаканов MEXC
.\.venv\Scripts\python.exe -m arbitrage --symbols ALL --max-connections 2 --mexc-depth-limit 10 --interval 5
# Показывать 10 строк со спредом от 0,01%; общий расчётный номинал двух ног 800 USDT
.\.venv\Scripts\python.exe -m arbitrage --min-spread-pct 0.01 --top 10 --capital-usdt 800
# Прежний REST-сборщик: пауза после завершения каждого цикла
.\.venv\Scripts\python.exe -m arbitrage --transport rest --watch --interval 15
# Все подходящие контракты: без дополнительных запросов стакана для каждого рынка
.\.venv\Scripts\python.exe -m arbitrage --transport rest --symbols ALL
# Отдельная биржа
.\.venv\Scripts\python.exe -m arbitrage --exchanges okx --symbols BTC,ETH
# Проверки без сети
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Результаты: `data/latest.json` и `data/market.sqlite3`. Время — Unix milliseconds UTC.
В JSON блок `scanner` содержит направления связок, спреды, справочные размеры и причины исключений.
В SQLite добавлена таблица `scans`; существующая `snapshots` сохранена.
Отрицательные спреды по умолчанию также сохраняются; `--min-spread-pct` задаёт фильтр,
а `--top` ограничивает только консоль. После остановки текущие строки скринера очищаются,
предыдущие расчёты остаются в истории SQLite.
Скринер принимает только свежие WS BBO: REST остаётся диагностикой без расчёта связок.
Для остальных монет сбор данных возможен, но сравнение исключается до явного добавления
проверенных соответствий в `arbitrage/instruments.json` (сейчас 60 записей для 10 активов).
Код завершения одиночного REST-запуска: 0 при успешных запросах всех выбранных бирж, 1 при ошибках.
В WS с `--duration` код 0 означает наличие всех запрошенных свежих котировок у всех выбранных
бирж на последнем рабочем снимке, без пропущенных рынков, отсутствующих активов и ошибок метаданных.
Код 1 означает неполноту: например, ALL упёрся в ёмкость либо тихий рынок помечен stale.
Само по себе это не означает обрыв соединения; в JSON видно точную причину.
При штатной остановке WS сохраняет итоговый статус `stopped`; данные нельзя принимать за действующий поток.
`quality` является оценкой на `quality_evaluated_at_ms`: при последующем чтении файла возраст нужно пересчитать.
Ctrl+C завершает наблюдение. При длительной работе SQLite растёт: ротация пока не реализована.
В REST ограничение цикла — 90 секунд на площадку. В WS загрузка рынков ограничена 60 секундами;
30 секунд без рыночных сообщений вызывают переподключение. Порог свежести каждой котировки — 3 секунды.
Тихий рынок может быть помечен stale даже при живом соединении. Pong не обновляет время котировки.
Метаданные обновляются каждые 900 секунд (`--market-refresh-seconds`, минимум 60).
Изменившиеся группы перезапускаются; если обновление не удаётся дольше двух интервалов,
котировки этой биржи исключаются до восстановления метаданных.

Если создание окружения завершилось ошибкой ensurepip, можно восстановить pip:
`python -m pip --python .venv\Scripts\python.exe install pip`, затем повторить установку.

## Дальнейший план

Актуальные этапы и статусы: [общий план](docs/ROADMAP.md).
Следующий шаг — завершение проверки охвата: полный нагрузочный прогон и расширение
проверенного реестра. Группы, обновление метаданных и стакан MEXC уже реализованы.
Затем — расчёт экономики связок.

Совпадение ticker/base не является доказательством идентичности контрактов.
Funding, open interest, оценка прибыли, фильтр истории funding и интерфейс ещё не реализованы.
KuCoin и LBank добавляются после проверки основных шести адаптеров.
Доступность торговли отмечена `not_checked` независимо от доступности рыночных данных.
Утверждения о тарифах и региональных правилах из прошлого диалога не считаются проверенными данными проекта.
