# Публичная совместная проверка

Стенд `validate_paper_live.py` запускает монитор, локальный UI, watcher переоценки
и watcher funding. В 0.32 флаг `--rules` добавляет пятый процесс автоматических
paper-правил. Каждый запуск использует новую
папку и отдельный свободный порт. Работающий пользовательский монитор не изменяется.

```powershell
Set-Location G:\Arbitrage
.\.venv\Scripts\python.exe validate_paper_live.py --directory data/paper-live-run-001 --duration 300 --port 8776
# Пять процессов; входами/закрытиями управляют штатные paper-правила
.\.venv\Scripts\python.exe validate_paper_live.py --directory data/paper-rules-live-001 --duration 300 --port 8776 --rules
```

Длительность: 60–86400 секунд, плюс загрузка/остановка. Это текущая команда,
а не служба или расписание. Нужен доступ к публичным API шести бирж. Funding-worker
работает без `--fetch-prices`; монитор независимо обновляет архив ставок через
обычное обслуживание. Реальных ордеров и внешних уведомлений нет.

Каждые 2с запрашиваются `/api/state`, `/api/paper`, `/api/alerts`, проверяются
свежесть confirmed, границы статистики и отсутствие подстановки неизвестного net.
На середине прогона перезапускаются созданные стендом paper-процессы (два или
три при `--rules`). UI и монитор продолжают работать.
В конце проверяются архивный режим, отсутствие текущих подтверждений и целостность
созданных SQLite. Все дочерние процессы завершаются в `finally`.

Без `--rules` стенд может открыть одну виртуальную позицию только по естественному confirmed
и после повторной проверки обычным `PaperLedger.open`. В последние 15с он пытается
закрыть её по свежим данным. Подтверждения и цены не подменяются. Если входа не было,
`paper_path=not_exercised_no_accepted_confirmed`; открытые/закрытые количества и
причины отказов сохраняются.

С `--rules` входы и закрытия выполняет только отдельный `arbitrage.paper_rules
--apply` на новом изолированном журнале, со штатными порогами. Клиент не вызывает
open/close и не форсирует выход перед окончанием прогона. Это позволяет проверить
реальное поведение правил, включая отсутствие подходящих сигналов. После остановки
монитора проверяется blocked rules-процесса, затем он завершается. Оставшиеся
открытые виртуальные позиции сохраняются, дальнейшей фоновой работы нет.
Автоматические правила пользовательского журнала этим флагом не включаются.

С версии 0.32 `paper_path` различает отсутствие входа
(`not_exercised_no_accepted_confirmed`), оставшиеся открытые позиции
(`entry_observed_positions_open`), закрытия с неполным funding
(`closed_funding_incomplete`) и покрытые закрытия (`closed_funding_covered`).
Последний статус означает полноту сохранённой модели funding, а не исполнение.
Исторический статус `exercised_natural_confirmed` в старых отчётах означал только вход.

`metrics.json` содержит задержки, состояния, перезапуск, целостность и отчёт монитора.
В rules-режиме сохраняются состояния, действия и причины отказов правил; действия
считаются один раз на timestamp статуса, а не на каждое HTTP-чтение. При опросе
возможны пропуски коротких состояний, поэтому позиции проверяются также в SQLite.
`persisted_evidence` агрегирует строки сохранённых economics/signal snapshots,
причины отсева и диапазон условного сценария. Это повторные наблюдения, не число
уникальных связок. События сигналов также сгруппированы по виду.
`state=passed`/код стенда 0 означают прохождение проверок совместной работы.
Это не критерий полноты рыночных данных или прибыльности. Смотрите отдельно
`market_data_quality`, `monitor_exit_code`, свежесть и ошибки каждой биржи,
`paper_path`, `paper_open_count`, `paper_closed_count`.

Ошибки HTTP/проверок и аварийное завершение worker дают failed. В первые 15с
допускаются только отказ подключения и timeout при запуске UI. Логи и промежуточные
метрики сохраняются при неуспехе. Для повтора укажите новую папку.

Пять минут без позиций не проверяют конкуренцию записи paper SQLite, восстановление
открытой позиции, исполнение или суточную устойчивость. Для контролируемой проверки
положительного paper-цикла есть отдельный `validate_paper_joint.py` с искусственными
данными; он не заменяет живую проверку.
