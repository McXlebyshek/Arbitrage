# Локальный интерфейс 0.14

В `G:\Arbitrage` откройте `Start-Monitor.cmd`, затем `Start-UI.cmd`.
Первое окно непрерывно собирает данные, второе открывает http://127.0.0.1:8765/.
Остановка каждого процесса — Ctrl+C в его окне. UI сам монитор не запускает.

Эквивалент запуска интерфейса из PowerShell:

```powershell
Set-Location G:\Arbitrage
.\.venv\Scripts\python.exe -m arbitrage.ui --open-browser
# Отдельно сохранённый двухминутный публичный прогон, только архив:
.\.venv\Scripts\python.exe -m arbitrage.ui --snapshot data/ui-live.json --database data/ui-live.sqlite3 --open-browser
```

По умолчанию используются `data/latest.json` и `data/market.sqlite3`.
Можно передать `--snapshot`, `--database`, `--registry` и `--port` (1024–65535).
При собственном реестре у монитора и UI должен быть одинаковый `--registry`.
Сервер слушает только 127.0.0.1; SQLite открывается в режиме read-only.
Статика поставляется с проектом, внешних CDN нет. UI не имеет методов отправки ордеров
или изменения настроек сбора, не требует биржевых ключей и не публикуется в интернете.

## Таблица и карточка

Режимы: лучшая связка каждого актива, все направления, выбранные расчёты экономики.
Доступны поиск, выбор обеих бирж, пороги спреда/условного net, готовность и сортировка.
Звезда сохраняет конкретное направление LONG/SHORT. Избранное и колонки хранятся
в localStorage браузера. Без сохранённых настроек при ширине меньше 1100 px три
дополнительные колонки скрыты; их можно включить. Таблица прокручивается по горизонтали,
карточки бирж в узком окне располагаются вертикально.

Нажатие строки открывает две ноги, bid/ask, funding, доступный оборот,
расчёт экономики, причины блокировки и последние события. Escape закрывает карточку,
`/` переводит фокус в поиск. При открытии другой связки старые значения очищаются.
Возраст данных обновляется каждую секунду; таблица опрашивается раз в 2 секунды,
открытая карточка — дополнительно раз в 9 секунд. Даты отображаются в Europe/Kyiv.

## Значения

- Вход, % = `100 × (SHORT bid − LONG ask) / LONG ask` — сырой исполнимый спред BBO.
- Выход, % = `100 × (LONG bid − SHORT ask) / SHORT ask` — обратное направление,
  с тем же знаменателем, что у соответствующей обратной строки сканера.
- Цены нормализованы к одной базовой единице по реестру, включая множители контрактов.
- Funding каждой ноги показан со своим периодом и временем следующего начисления.
  Разные периоды не вычитаются напрямую. «F net 24ч» — сумма наблюдавшихся ставок SHORT
  минус сумма ставок LONG за покрытое окно 24ч, при условном одинаковом номинале.
  Это сравнение истории ставок, не фактические денежные начисления позиции.
- Условный net берётся из модели экономики: общие размер/бюджет, VWAP, четыре комиссии
  и funding-сценарий. Будущая цена выхода и тариф аккаунта не подтверждены.
- Неизвестное обозначается прочерком. Нулём оно не заменяется; APR и OI пока отсутствуют.

## Свежесть и архив

Живой снимок должен быть не старше 5 секунд. Для действующей связки обе котировки
проверяются по исходному и локальному времени: до 3 секунд, допуск будущего времени 1 секунда.
Текущее подтверждение дополнительно требует глубины обеих ног до 3 секунд и,
при ненулевом funding-горизонте, funding до 120 секунд. Клиент пересчитывает свежесть
между ответами сервера. Это допуск данных модели, не подтверждение реального исполнения.

Если свежих строк нет или монитор остановлен, UI может показать последний непустой
снимок из последних 50 записей сканера. Он явно обозначен архивом; текущие подтверждения
сняты, отсчёт funding относится к времени снимка. Отсутствие истории даёт пустое состояние.
Ошибка чтения текущего JSON допускает показ архива с пояснением.

## Графики и оставшаяся работа

Вкладки: сырой спред входа/выхода, цены входа обеих ног, исторические начисления funding.
Нижняя панель синхронизирована с текущими наблюдениями ставок. Курсор показывает значения,
ползунок оставляет последние 20–100% наблюдений; кнопка сброса возвращает весь набор.
Пропуски более 10 секунд между сырыми наблюдениями не соединяются линией.

Окна 1/15/60/360 минут читают **не более 300 последних снимков** сканера;
наблюдения ставок также ограничены 300 снимками экономики. Поэтому окно 6ч не обещает
шесть часов непрерывной истории. Число точек и усечение показаны в карточке.
Фактические события funding за последние 30 дней читаются отдельно из импортированной
истории (до 1000 событий на ногу); новая база без импорта не содержит этого ряда.
Интерполяции и искусственных точек нет.

Этап 9 выполнен частично. Следом нужны графики длительных периодов на минутных сводках,
проверка производительности большой истории и продолжительная проверка UI вместе с монитором.
Протокол текущей проверки: [UI_CHECK.md](reports/UI_CHECK.md).
